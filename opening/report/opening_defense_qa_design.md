# 开题答辩 QA 预演手册设计

日期：2026-08-25

## 1. 目标

基于当前最终开题报告、用户提供的 50 题预演稿和现有 `opening/qa_bank.md`，生成一份中文 A4 答辩手册。手册同时服务两种用途：现场能快速找到并说出 30--60 秒主答，连续追问时又能查到证据、适用条件和不能外推的边界。

## 2. 读者与口径

- 读者是开题答辩现场的报告人，不假设熟悉项目内部代号。
- 以 `opening/report/opening_report.md` 为事实与叙事基线，以 `opening/claim_matrix.md` 和真实结果报告限制证据等级。
- 已完成的工作用完成时；尚未完成的 PostgreSQL planner-visible AI 算子、完整状态感知方法和 SQL 计划级代价选择用将来时。
- 统一表述为“PostgreSQL 内置 LOTUS AI 语义算子的外部分布式物理执行与调度优化”；不修改 PostgreSQL core、vLLM continuous batching、模型内部或 Ray scheduler。

## 3. 文档结构

1. **使用方法**：统一答题顺序，区分已完成、前期证据和计划验证。
2. **14 个必背核心问题**：课题概括、数据库属性、创新、与现有工作的区别、两项研究内容、完成状态和负结果边界。
3. **研究方案总体追问**：从 SQL 入口到模型结果返回的整体链路、两项研究内容的接口、基础方法与代价信息增强的区别、独立优化与联合调整的验证顺序。
4. **研究内容一：分阶段工作量表征与数据组织**：作为最详细的两个主体之一，覆盖 WorkDescriptor 字段来源、可观测事实与预测值分离、未知输出长度、分阶段向量与准入标量、兼容性分组、token/frame budget、length alignment、prefix/locality 保留、受控跨组平衡、有界流下的在线组织、SQL 顺序语义、能力降级和分阶段消融。
5. **研究内容二：固定容量下的提交、路由与多 Job 调度**：作为另一个详细主体，覆盖 Request/Work Credit、completion-driven replenishment、RuntimeStateSnapshot、硬约束与软决策分层、Job floor/cap、实际服务量记账、SLO guard、idle borrowing/reclaim、endpoint 路由、locality 与队列折中、非抢占性、状态过期回退、振荡抑制、并发一致性、取消与故障。
6. **PostgreSQL、LOTUS 与代价估计**：详细解释 planner hook/CustomScan 候选、bounded RowEnvelope stream、row identity、cancel/error/result lifecycle、\texttt{sem\_map} 语义复用、物理 backend 替换、代价特征、不确定区间、候选排序与 decision regret。
7. **实验设计、baseline 与证据边界**：因果消融、固定总容量、最小饱和点标定、交错重复、跨框架比较合同、质量与 correct throughput、sink 边界、跨模态复用和外部有效性。
8. **可行性、风险与新增攻击面**：隐私与外部模型服务、状态采集开销、控制层扩展性、模型非确定性、事务可见性、多租户边界、组合已有组件是否构成创新、方法不胜出时的论文成立条件。
9. **连续追问链**：数据库属性、研究内容一技术链、研究内容二技术链、与 serving 调度的区别、当前结果不全面胜出、实验可比性、系统故障七条链。
10. **速查页**：研究方案口述流程、两项内容的输入--决策--输出、关键数字、完成状态、对比工作层次与答辩红线。

## 4. 单题模板

每题最多使用五个部件：

1. **问题**：使用老师可能采用的质疑式问法。
2. **一句话结论**：先直接回答“是/不是/为什么”。
3. **30--60 秒主答**：按“结论—边界—证据—后续验证”组织，语句可直接口述。研究方案和两项研究内容的高频技术题可扩展到 60--90 秒。
4. **按步骤讲**：只在方案题中使用，用 3--6 个编号步骤说清输入、约束、决策、状态更新、输出和回退路径，避免只给抽象名词。
5. **追问时补充**：列出必要的数字、条件、反例、参数来源或消融方法；没有实质补充时不强行保留。
6. **可能继续追问**：对研究方案高风险题列出 1--3 个紧接着可能出现的问法，并给出可跳转的相关题号。
7. **证据状态/不能声称**：用简短标记区分已完成事实、前期证据和计划验证，对高风险问题明示禁止外推的说法。

## 5. 内容规模与去重

- 用户附件中的 50 题全部覆盖，允许为避免重复而合并部分主答，但要在题目索引中保留可查找的问法。
- 从现有 `opening/qa_bank.md` 提取不重复的 baseline provenance、database-E2E correctness、feeding-saturation、arrival contract 和跨模态证据边界。
- 新增约 25--35 个高价值问题，总题数预计 75--85；新增题主要投入研究方案、两项研究内容和技术可证伪性，不为追求数量拆分近义问题。
- 研究方案及两项研究内容预计占全部题目的 45\%--55\%，且每个核心模块至少同时回答“怎么做”、“为什么这样做”、“怎么验证有用”和“什么情况下回退”。
- 普通主答尽量不超过 180 个汉字；方案技术题可扩展到约 300 个汉字，并使用 3--6 个短步骤，但不将同一段抽象架构话在多题中重复粘贴。

## 6. LaTeX 与 PDF 设计

- 产物：`opening/report/opening_defense_qa.tex` 与本地可再生成的 `opening/report/opening_defense_qa.pdf`。
- 使用 A4 `ctexart` + XeLaTeX，保留可点击目录和 PDF 书签。
- 一级章节区分攻击面，每题用不编号的短标题和页边防孤标题规则；“一句话结论”、“追问时补充”、“证据状态”使用稳定的视觉标记。
- 版式以可读性为先，不通过过小字号强行压缩页数；由于方案题增加了步骤化回答和连续追问，预计 30--45 页。
- PDF 与 LaTeX 中间产物按仓库 `.gitignore` 规则作为本地可再生成文件，跟踪 `.tex` 源文件。

## 7. 验收与同步

- 结构检查：问题数、必背题数、新增问题数和证据状态标记数符合设计。
- 内容检查：搜索“已经实现/已经优于”等高风险完成时表述，核对 PostgreSQL 18.3/18.4、65,536、Jain、代价选择损失等数字的条件。
- 编译检查：XeLaTeX 连续编译两次，无 LaTeX error、undefined reference 或行宽越界。
- 页面检查：渲染全部 PDF 页面，检查目录、分类起始页、高密度问答页、速查页和最后一页的裁切、孤标题与留白。
- 文档同步：更新 `opening/README.md`、`PROJECT_INDEX.md`、`opening/logs/project_log.md` 和根 `PROJECT_LOG.md`；不修改开题报告、PPTX、飞书发布面或实验结论。
