# 开题工作规则

## 工作目标

开题阶段要证明：

- 题目有研究价值。
- 问题定义清楚。
- 技术路线可执行。
- 前期准备有基础。
- 后续计划能落地。
- 风险和边界自己知道。

开题不是最终成果发布。更稳的说法是“当前实验作为可行性依据，后续会扩大验证”，不要说“已经完整证明”。

开题也不是项目之外的附属材料。报告中确定的题目、研究内容、评价指标和边界，会反向约束后续项目规划、实验优先级和对外沟通口径。修改这些内容时，需要同步检查项目级 `README.md`、`PROJECT_INDEX.md`、`PROJECT_OUTLINE.md`，以及 `opening/README.md`、PPT、飞书源稿和问答材料。

后续每次调整开题报告，需要先判断调整类型：

- 只改语言、格式、图表位置：通常只同步报告、PPT、飞书源稿和日志。
- 改题目、研究问题、研究内容、创新点、技术路线、实验优先级或适用边界：必须同步检查项目级 README、`PROJECT_INDEX.md`、`PROJECT_OUTLINE.md`、`motivation/plans/workloads.md`、`motivation/plans/integration.md`、PPT、飞书源稿、问答材料和项目日志。
- 改实验结论或新增实验依据：必须同步检查对应的 `motivation/results/` 或 `feasibility/results/` 报告、学习材料和开题可行性分析。

## 当前工作顺序

当前阶段先不生成 DOCX，优先级如下：

1. 本地 Markdown 源稿：报告、飞书稿、PPT 源稿先在本地统一口径。
2. 飞书文档补全：飞书文档是发布面，内容来自本地 Markdown。
3. PPT 制作：基于报告和图表做现场汇报版本。
4. PPT 同步飞书：把 PPT 核心内容同步到飞书。
5. DOCX 生成：最后使用学校 Word 模板生成正式提交版。

最终 DOCX 必须使用学校模板，不从空白 Word 文档生成；需要继承模板中的章节字体、正文宋体 / Times New Roman、小四号、1.5 倍行距、两侧对齐、图表标注和参考文献格式。

## 写作原则

- 少用空泛判断。不要只写“具有重要意义”，要写清楚重要在哪里、对应什么问题、后续怎么验证。
- 先建立论证树，再划分章节或页面。统一顺序为“总动机 → 子问题 → 证据实验 → 观察结论 → 研究问题/研究内容 → 技术路线”。如果只有实验清单而没有一句能够概括全部实验的父命题，说明层级尚未建立，不能直接进入正文。
- 同级项目必须同类且粒度相近。总动机描述普遍不足，子问题描述不足的不同方面，实验任务验证子问题，研究内容提出稳定的解决方向，实现任务说明如何落地。不得把状态观测、动态动作、代价估计、跨模态验证和若干实验任务无条件列成平级研究动机。
- 每轮修改执行三项层级检查：父项覆盖检查，确认父命题能解释全部子项；兄弟同类检查，确认同一列表不混合问题、证据、方法和实现；收敛检查，确认每组证据最终只导向既定研究问题，不因任务增多而新增研究内容。
- 当前正文使用“三个动机实验对应两项研究内容”的稳定结构：固定行数不能表示 AI 工作量对应研究内容一；单一要素不能代表当前运行状态、总体效率不能代表各作业完成结果，这两组实验共同对应研究内容二。代价估计和跨模态实验只承担共同使能与验证作用。
- 代价估计的角色分三层说明：主要服务数据库侧的计划与多 SQL 运行安排；在独立数据上验证可靠后，可以把预计批次时间或资源需求作为研究内容一的可选输入，把预计服务时间、剩余工作或服务目标余量作为研究内容二的可选输入；两项研究内容先建立依据可观测特征、容量和实际状态运行的基础方法，再用实际系统指标检验接入预测后的额外收益。
- 正式材料优先用正面句说明研究对象是什么、位于哪里、接收什么信息并发挥什么作用。对读者尚未接触的内部分类争议不作否定式回应；“没有证明什么”“哪些条件下不成立”等表述主要用于实验结论、实验总结和文献适用条件。
- 论文名称使用正式英文原题，中文只承担内容解释。正文不使用书名号包裹自译的中文论文题名。
- 引用采用“正式版本优先、版本证据分开”的顺序：先查会议/期刊官网、正式 proceedings 或 DOI，再查作者主页和 DBLP，最后才使用 arXiv。已录用但尚未生成卷期、页码或 DOI 的论文，只写官方能够证明的 `accepted`/`to appear` 状态；若精读仍基于较早的 arXiv PDF，方法和实验数字注明该版本，避免混版。
- 解释动机二、三为何共同对应研究内容二时，必须写出共同决策点，不能只给对应关系：模型服务状态回答“何时继续提交、发往哪个服务实例”，逐作业状态回答“有空间时下一份工作来自哪个作业”，两者共同决定下一份工作何时发、发给谁、发到哪里，分别落到提交控制、服务实例路由和多作业调度。
- “有层次”不等于增加标题数量。优先用段首总述建立父命题，用过渡句说明子实验各自验证什么，用段末一句把观察收束到研究内容。研究内容一先说明“分阶段工作量表征、数据组织”两个环节；研究内容二先说明“单一维度无法完整表示运行状态”的总问题，再说明“提交控制、服务实例路由、多作业调度”三个组成部分。动机实验二和三分别从模型服务状态、逐作业状态支持这一总问题。
- 图文执行同一语言检查。图题写清“在什么条件下观察到什么”，分图标题写清该子图排除了哪一种简单解释；内部结构名和英文指标首次出现时，在图内或紧邻图注补充中文作用。只写“状态不足、证据链、候选组合、能力边界”等分类词而不说明对象和现象，视为未通过检查。
- 图中允许保留能够帮助解释执行方案的数据结构和物理量，但不得保留项目内部的流程管理词。颜色语义固定为：蓝色研究内容一，橙色研究内容二，紫色共同使能或公共执行部分，绿色结果/评价/写回，灰色观测和说明。已有必要架构图和研究内容图优先做局部修改，不为相同叙事重复新增图。
- 研究内容不能写成工程任务清单。每一项研究内容要按“问题、技术难点、拟采用方法、评估方式”组织，回答为什么难、怎么解决、如何证明有效。
- parser、worker、endpoint、写回、实验脚本等工程步骤放在技术路线或进度安排里；研究内容必须写成可检验的研究问题。
- 研究内容需要包含对比对象、评价指标、消融实验和适用边界，避免写成“把几个模块做完”。
- 进度安排使用多月阶段范围，例如“2026 年 8 月—2026 年 11 月”或“第 1—3 个月”，不按单月逐项罗列。每个阶段只写一个主要研究或验证目标，不展开参数、实验臂和实现清单；除非学校模板明确要求，不把开题材料、学位论文撰写、送审或答辩准备列为研究进度。
- 第一章的修改以保留解释清晰度为先，只收回提前出现的实现细节和实验数字。国内外研究现状的核心要求是“充分综述相关文献”，而不只是“不用表格”：先覆盖与课题直接相关的主要方向，再从 `research/精读文献笔记/` 的当前权威精读和 `opening/literature/top15_reading_notes/` 的适用快照中选出核心文献，逐篇或按紧密关联的小组较详细地说明问题、方法、证据、局限及与本课题的联系；其余文献用于补足脉络和横向比较。问题表不进入正文，且不得用文献列表或对照表替代连续综述；第一章之外原则上不新增表格。
- 创新点要克制。开题阶段写“预期创新点”，不要写成已经完成的创新成果。
- 所有结论都要有边界：当前能说明什么、不能说明什么、后续怎么验证。
- 写实验结论和分析实验数据时，参考 `learning/AGENTS.md` 的精细程度：说明实验目的、链路流程、参数含义、数据来源、结果读法、不能证明什么、下一步怎么验证，并区分本地实验事实、模拟实验事实、合理推断、待确认问题和不能声称的结论。
- 报告、PPT、飞书版、Word 版不能出现不同题目、不同研究内容或不同实验口径。

## 高频答辩策略

老师质疑时，回答结构优先采用：

```text
先承认问题存在
  -> 说明当前为什么这样处理
  -> 说明后续如何补充验证
```

不要和老师争“已经证明了”。开题阶段主动承认边界通常更稳。

## 最终检查

- 题目、研究目标、研究内容一致。
- 报告结构符合学校模板。
- DOCX 使用学校 Word 模板生成，并继承模板格式。
- 参考文献数量、外文比例和精读文献数量满足要求。
- 15 篇精读文献能讲清楚。
- PPT 和报告口径一致。
- 技术路线能对应后续实验和实现任务。
- 创新点没有夸大。
- 局限和风险已主动写入。
- 答辩备注准备了常见问题。
- 所有非实验类修改已记录到 `logs/project_log.md`。
