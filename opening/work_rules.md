# 开题材料变更路由清单

> 本文件不是独立规则源。处理跨报告、PPT、飞书、文献和答辩材料的任务时，在根 `AGENTS.md` 与
> `opening/AGENTS.md` 之后读取本清单；单文件小改无需加载。当前材料状态见 `README.md`。

## 1. 先判断变更类型

| 变更类型 | 先核对 | 需要同步的发布面 |
|---|---|---|
| 语言、格式、位置 | 当前源文件、模板、受众语言规则 | 只更新实际受影响的源与导出；记录 opening log |
| 题目、研究问题、研究内容、创新点 | 根规则、`PROJECT_OUTLINE.md`、claim matrix | 报告、PPT、飞书、问答；同时检查根入口和项目日志 |
| 实验结论或评价口径 | 原始结果、证据台账、结果 README | 实际引用该结论的报告、PPT、图和飞书段落 |
| 文献题录或相关工作判断 | `research/` 权威笔记、正式题录、阅读版本 | 报告引文/题录、开题清单、PPT 参考页、文献日志 |
| 图表数字、标题或读法 | 图源、脚本、CSV/manifest、figure audit | 所有实际引用该图的材料 |

不要按目录清单机械修改。先用 `rg` 找真实引用和受影响事实，只同步必要文件。

## 2. 权威源与发布面

- 报告 Markdown、PPT 可编辑源、图源和 `research/` 笔记是可修改的权威输入。
- DOCX、PDF、PPTX 和飞书是发布面；生成成功不等于版式或远端内容已经验证。
- 报告、PPT 和飞书可以详略不同，但题目、两项研究内容、证据数字、限制和下一步一致。
- 开题快照不反向覆盖 `research/` 精读；发布稿不反向覆盖原始实验结果。

## 3. 执行顺序

1. 读取根规则、`opening/AGENTS.md` 和目标文件；确定读者与变更类型。
2. 从原始结果/源码/正式题录核对事实，列出实际受影响文件。
3. 先改权威源，再更新需要的发布面和导航。
4. 对读者型文件执行根“文档受众与对外表达”搜索；每个命中均已改写或解释。
5. 图/PPT/Word/飞书分别执行视觉或远端内容验证；无法验证时写 `pending`。
6. 非实验 opening 变化写 `logs/project_log.md`；影响全项目入口、方向或结论时同时写根
   `PROJECT_LOG.md`。

## 4. 完成检查

- 父问题能概括全部子项，同级项目同类且粒度接近；
- 证据实验只支持其对应子问题，不从实现任务直接推出研究贡献；
- 数据、版本、引用和图表均可回到原始来源；
- 初步结果没有写成最终贡献，限制和后续验证清楚；
- 需要的导出已实际打开检查，远端发布已读回；
- 未修改的发布面没有被声称已同步；
- 日志只记录本次真实变化。
