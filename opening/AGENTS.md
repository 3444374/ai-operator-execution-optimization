# opening/AGENTS.md

本文件继承根 `AGENTS.md`，只增加开题报告、PPT、答辩、飞书发布面和开题文献快照规则。目录入口
与当前发布状态见 `README.md`、`navigation.md`；本文件不保存页数、当前进度或实验数字。

## 1. 目标与目录

开题材料要证明研究问题有价值、对象和边界清楚、路线可执行、前期证据足以支持继续研究；不能写成
项目已经完成或方法已经胜出的宣传稿。

- `report/`：报告正文、学校模板与格式适配；
- `slides/`：PPT 源稿、备注和导出；
- `feishu/`：飞书发布稿；
- `literature/`：开题清单与 Top 15 快照；新的权威精读仍在 `research/精读文献笔记/`；
- `assets/`：开题专用模板/素材，不复制 `figures/` 的正式图；
- `logs/`：非实验类开题变更日志。

跨报告/PPT/飞书/文献的联动修改再读 `work_rules.md`；实际创建、编辑或导出 PPT 再读
`ppt_rules.md` 和 `figures/AGENTS.md`。两者是按任务触发的专项清单，不能覆盖本文件或根规则。

## 2. 事实与论证结构

- 每个结论区分论文/官方资料、本地原始实验、实现事实、合理推断和待验证问题。
- 初步结果写“可行性依据、观察信号或待扩大验证”，创新点写“预期创新点”；不能把计划当贡献。
- 动机按“总动机 → 子问题 → 证据实验 → 观察 → 研究内容”组织；实验脚本、参数、对照臂和模块
  不能与总动机或研究内容并列。
- 同一标题组、表格或连续页面的兄弟项保持相近粒度，每个证据回到唯一上位问题。
- 研究内容固定为两项：分阶段 work 表征与数据组织；提交控制、服务实例路由和多作业调度。代价
  估计是共同支撑，跨模态是验证角色，写回是工程 baseline。
- 服务侧状态回答“何时提交、发往哪里”，Job 状态回答“下一份工作来自哪个作业”；用这条因果关系
  连接提交、路由和多 Job 调度。
- 第一章保留读者理解数据库记录、AI operator、外部 backend 和结果写回所需的最小运行例子；具体
  实现、参数和实验数字在后文出现。

## 3. 写作与图表

- 对外对象使用根规则规定的 PostgreSQL/LOTUS 表述，不把 Ray、Daft、Lance 或某个产品写成课题本身。
- 说明角色、输入、输出、作用位置和适用条件；减少宣传式形容、连续抽象名词和只有项目成员理解的
  管理词。定稿前搜索内部代号、未解释英文和高风险项目管理词并逐句改写。
- 论文题名使用正式英文原题；系统名可保留英文，中文负责解释问题、方法、结果和限制。
- 报告至少保留研究对象图、两项研究内容的方法图和总体实验方案图。已有图能回答同一问题时修改
  可编辑源，不新增近义架构图；颜色和视觉规则继承 `figures/AGENTS.md`。
- 图题写清比较对象/条件和观察；caption 说明读法、数据来源、主要现象与不能推出的结论。
- 正文层级优先通过段首总述、过渡和段末收束表达，不为强调结构制造大量短小标题。
- 进度安排按多月阶段写目标，不逐月罗列参数和实现任务；学校模板另有要求时以模板为准。

## 4. 文献

- 优先 CCF-A 正式 research paper，再补高相关 CIDR/MLSys/tutorial/benchmark/arXiv、官方文档和源码。
- 题录按会议/期刊官网、proceedings 和 DOI 核验。只有预印本时记录 arXiv version；已录用但卷期、
  页码或 DOI 未发布时写 `accepted/to appear`，不补造出版信息。
- 本地阅读版本与正式发表版本不同时分别记录；查询数、数据集、Figure/Table 和实验数字必须注明
  来自哪个版本。
- 研究现状用连续综述解释代表工作的研究问题、方法、实验、限制和与本课题关系，不用一张对照表
  代替全文论述。
- 开题报告采用顺序编码制：按正文首次出现分配编号，检查编号连续、题录一一对应、无未引用条目。
- 文献变更先更新 `research/` 权威材料，再更新开题快照；开题快照不反向覆盖精读主笔记。

## 5. PPT 与人工编辑保护

- 学校模板提供母版、占位符、主题字体、页眉页脚和安全内容区，不作为整页背景截图。
- 每页一个主结论，解释进入备注；备注默认包含 `汇报讲稿` 与 `答辩备注`。
- 生成或修改后必须在 WPS/PowerPoint 中实际打开，检查溢出、字体替换、图表可读性和备注。
- 用户已经手动调整现有 PPTX 时，只做 shape 级增量修改；未经明确授权不重新运行全量 builder 覆盖。

## 6. 发布与同步

- 本地 Markdown/可编辑源是权威稿；PPTX、PDF、Word 和飞书是发布面。发布前先验证本地稿，再验证
  实际导出或远端页面；不得把“已生成/已上传”写成 live verified。
- 题目变化同步报告、封面、PPT、飞书标题和根方向入口；研究内容变化同步技术路线、创新点、进度和
  答辩备注；实验口径变化同步实际受影响段落与图，不全量机械重写。
- 报告负责完整论证，PPT 负责现场讲解，飞书负责发布摘要；三者可以详略不同，但事实和边界一致。
- 普通飞书文档、Base 和飞书幻灯片使用各自连接器/skill；只有用户提供目标并授权写入后才发布。
- 非实验类变更记录到 `opening/logs/project_log.md`；影响项目结构、方向、结论或入口时同时记录根
  `PROJECT_LOG.md`。
