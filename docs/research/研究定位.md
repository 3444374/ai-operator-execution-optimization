## 研究对象与问题

当前课题研究**AI 语义算子与多模态数据任务的物理执行、数据组织与调度优化**，SemLoom 面向语义 API 与数据库等前端。
PostgreSQL 是数据库接入场景之一，拥有该路径的 SQL、关系输入、快照、权限及查询生命周期；
LOTUS、Palimpzest 等语义前端保留各自算子与计划职责。外部执行层在合法任务与实际资源范围内组织数据、
提交请求并选择执行服务。两项研究内容是数据组织，以及固定容量下的提交、路由与同租户多查询调度。
算子代价估计提供共同信息，图像任务用于检验跨模态适用性。

数据库提供的合法需求、任务依赖、消费进度与取消约束应进入机制，确定哪些准备、提交、重排和释放动作可以执行。
近期首先检验单查询／一批数据能否少准备、少搬运、少做重复计算，从而改善完整任务时间与有效吞吐；
多查询服务分配作为后续适用问题。核心待证问题是：数据库信息能否产生超过合理原生路径的净增量；
这种收益是否足以覆盖读取、表示、预测、传输和控制本身的成本。
有限窗口、长度排序、工作量控制和状态反馈都是候选动作，采用哪一种取决于匹配对照与实际证据。

工程检查先确认语义、关联、取消和资源责任可核验；方法比较再检查相同工作和实际资源下的净收益。
独立执行核心可以使用身份明确的外部工作负载或受控输入开展研发，数据库接入与真实模型评价分别满足自身条件。

<a id="platform-and-work-contract"></a>
### 平台目标、工作表达与可控动作

架构目标是面向模型关键数据任务的可复用执行核心，当前能力限于已有任务、协议与适配的验证范围。
具身离线多模态数据处理属于待验证的未来应用，需要另行验证输入表示、依赖、消费方式和资源约束；
在线控制与训练不在当前承诺范围。

完整请求语义合同约束调用输入、模型与生成参数、行关联、结果及错误／取消规则。
工作量和阶段表达描述同一任务的物理需求，并保持上述调用语义：已有[WorkDescriptor／StageWork](https://github.com/3444374/ai-operator-execution-optimization/blob/9c59dc9be1422fca2ef75a4b4f4d41a65eb1100e/code/src/planning/work.py)
记录阶段、工作量单位、局部性、校准签名和不确定性，供组织、准入及路由使用。
[完整任务入口](https://github.com/3444374/ai-operator-execution-optimization/blob/9c59dc9be1422fca2ef75a4b4f4d41a65eb1100e/code/src/execution_provider/adapters/native_tasks.py)与
[默认Map描述](../../code/src/execution_provider/adapters/incremental_execution.py)采用的`work=1`表示请求计数；
成本自适应仍需有效估计、校准、实际决策及净收益证据，不能由类型或单位字段的存在推定。

Ray、Daft、IMLane已有执行、分批与背压机制。接口接通、任务关联和统一字段属于工程基础，
算法增量要落实为具体可见信息、合法动作及相对合理原生路径的收益。
当前HTTP路径的可控能力称为请求准入、在途work控制和服务路由；
模型内部 tensor／KV、执行与GPU资源安排由相应服务拥有，这些外部动作不表示精确GPU算力分配。
SemLoom 利用 Ray Core 的任务、actor 与对象设施；Ray Data 是拥有数据流执行的数据引擎，
与 SemLoom 的数据执行职责有重叠，合理调优的原生 Ray Data 始终是强参照。

近期候选是在固定资源下，结合阶段工作量联合选择**表示路径、合法消费者顺序、表示存活与提交机会**；
它是待验证问题，不是已采纳创新。先确认真实近期消费者及其需要的表示／变换和消费时刻；
单遍CLIP没有重复消费需求时，不能凭缓存接口或驻留声明证明复用策略有效。
合法结果缓存与索引复用保留为完整应用的强参照，实际模型调用／work分别报告，不把少做模型计算都归因于准备或提交策略。
具体身份与实施落点见[共享准备切片](../../experiments/plans/数据组织.md#scene-preparation-pilot)。
已有高效静态流水及合理原生路径继续保留，不把batch、背压、缓存或融合本身作为创新。
[单GPU诊断顺序](../../experiments/plans/数据组织.md#single-gpu-image-critical-path)先核实完整查询瓶颈再决定有限调参。
先检验当前单查询数据执行；多GPU、拓扑组和跨卡传输作为后续扩展，复用已有dispatcher，训练属远期；由实际瓶颈决定是否推进。
默认 dispatcher 为 static，locality 的 unknown／unsupported 不改变路由；多 GPU、直传与复用组合收益未验证。
表示／中间物化及 uint8 延后 FP32 扩展／批次切分仅有云端 CPU 探索，未采纳为本基线创新或验证 GPU 收益。

<a id="palimpzest-comparison"></a>
### Palimpzest 的系统与执行比较边界

Palimpzest（PZ）与 LOTUS 是平行的语义系统参照：PZ 提供语义算子、优化器与执行前端，不是 LOTUS 的后端。
[CIDR 2025 正式论文](https://www.vldb.org/cidrdb/papers/2025/p12-liu.pdf) §3–5 已覆盖逻辑／物理计划搜索、
time/cost/quality 取舍及 convert/filter 的并行实现；原生对照应保留合理并行，不能用单线程弱化它。
[Abacus 正式论文](https://www.vldb.org/pvldb/vol19/p1060-russo.pdf)（PVLDB 19(5), 2026）§2–4 描述在 PZ 中实现的
优化器，利用算子采样与 Pareto-Cascades 选择计划；这些已有能力约束本项目的增量主张。

完整系统比较允许 PZ、LOTUS 等选择不同合法计划，同时评价结果质量、费用与完整完成时间；
PZ 加不同执行后端的比较则固定同一物理计划及语义合同，再判断执行方式的净影响。
五组目标、版本锁定及实际准入要求由[对照规范](../../experiments/plans/reference/对照规范.md#palimpzest-fixed-plan)维护；
目标列入文档不表示接入、真实模型或性能资格已经完成。

**候选登记：消费进度感知的有界组织。** 来源为当前执行证据、用户研究审查和上述近邻之间的待证问题，
不是已证明的新算法。比较少量合法、尚未提交的动作，估计查询推进与驻留代价，预测优势不足时保留调优静态动作。
需要先用全局元数据、同信息FIFO/长度策略和既有公平控制否定容易成立的解释，才能判断数据库消费位置是否提供新决策价值。
如果全局信息更便宜有效，或强静态已足够，应收敛为该方案，而不是维护有限窗口偏好。

2026-10-02：[数据执行与模型服务协同候选](优化方法依据.md#serving-cooperation-candidates)
进一步登记输入/输出工作分解、消费进度、软前缀亲和、准备表示、依赖推进和同租户多 Job 的候选动作及反证。
这些分析不预选有限窗口、不把已有异步流水作为新增贡献；正文与文献依据维护在方法文档，执行安排仍引用现行计划。
训练供给仅为后续适用问题，样本及训练接口尚未实现。

2026-10-03：[多粒度与链路准入评估](优化方法依据.md#granularity-admission-assessment)将准备、物化、
传输、模型提交及结果消费的不同作用点分开。待证增量是付费信息下的联合选择是否优于已解耦粒度和强静态，
不以“推理前”代替“准备前”，也不预先要求多实例、语义连接或训练。新增文献题录从清单核对。

同日[完整流程与场景分层分析](优化方法依据.md#query-specific-execution-opportunities)进一步收窄候选：
利用已经定义的合法行/窗口、共享资产关系和实际消费需求，选择必要准备及保留/释放时机。
多模态和具身离线数据用于检验这些信息的决策价值；当前没有相应完整窗口算子、trainer或在线动作接入。
具身离线数据处理作为可扩展验证场景，比较时明确任务单位、视角、采样、时间窗口和质量目标；
为筛选或跳过样本实际付出的读取、解码与选择仍计入处理工作。这一场景不表示真实机器人或闭环验证。
SQL筛选、按episode读取、确定性缓存和异构流水已有直接参照；新增贡献须超过同信息量的原生方法，
不能从场景名称、版本管理或接入能力本身推出新颖性。

同日[异构需求补充](优化方法依据.md#heterogeneous-demand-supplement)把SSD、内存、CPU、GPU与网络
纳入同一数据路径，但分别表达计算服务、移动、驻留和位置。待证问题收窄到合法需求变化时，
物理读/解码依赖、表示及保留时机是否优于同信息的原生方法；不增加通用异构调度研究内容。
Scanner、VStore、cedar与Plumber已覆盖需求反推、格式选择、组合优化和资源画像，
新增比较需保留输入/状态/随机语义，提前准备还要明确求值许可、延迟错误与退出等待。
这些候选尚未成为PG窗口或训练接入能力，题录与具体动作分别回到文献清单及方法/实施文档。

同日[执行层分工评估](优化方法依据.md#engine-ownership-assessment)明确Core运行时、原生Data/Daft执行器
与模型服务的不同职责。方法可落在已有adapter或有限引擎接口，先证明具体信息与物理动作的净增量；
固定任务执行和完整语义系统分别比较，训练供给仍为后续适用问题。
原生Daft的延迟昂贵projection与固定版本批内媒体解码须进入强对照，逻辑筛选不能替代物理少读证据。

模型中的每个动作必须对应真实读取、准备、提交或释放变化；精确GPU剩余时长、实时KV驻留、token抢占都不是当前黑盒端点的已知能力。
早期“同质或异质分组更适合某服务模式”和“解析公式直接选择K”的建议作为条件性迁移假设，
不因出现在本文就视为数学依据。原实验数字只由其原始报告解释，不在本节重算或改写。

<a id="evidence-requirements"></a>
## 判断增量所需的证据

任务级目标是在保持任务语义、质量要求与实际资源约束的前提下，缩短以模型推理为关键环节的数据任务
从到达至结果可用的时间并提高有效吞吐；共享负载的服务质量作为后续问题。就绪后的执行时间帮助解释机制；
[固定集成来源的任务计时与工作量口径](https://github.com/3444374/ai-operator-execution-optimization/blob/9c59dc9be1422fca2ef75a4b4f4d41a65eb1100e/experiments/plans/语义系统对照.md#task-timing-boundaries)区分两种区间与各类工作。

实现按以下切片收集证据，仍对应前述两项研究内容：

| 实现切片 | 要解释的任务级结果 |
|---|---|
| query：完整查询执行 | 先检验单查询／一批数据提交至全部结果；后续多查询再评价长短查询体验与同资源独占参照下的干扰 |
| stage：准备与阶段组织 | 当前准备路径中真实表示的生存期、复制、驻留与阶段重叠，及其对完整任务关键路径的影响 |
| replica：服务副本路由与准入 | 固定资源与合理静态参照下的任务完成时间和有效供给；请求数均匀或队列较短不能单独证明收益 |

- 先区分减少模型工作、相同工作执行更快、资源能力与工程修复。模型、语义或输出改变时同时评价质量与实际工作量。
- 信息取得、分词、表示、预测、组织、序列化、传输和控制的成本计入完整查询；局部阶段改善还需完整查询完成时间（JCT）支持。
- 用合理调优的静态路径与同信息的简单策略检验候选。历史外部执行、受控输入和数据库接入结果保留各自身份。
- 共同积压时的服务分配、查询完成体验和干扰分别评价；公平指数不能独自替代最差查询、尾延迟与资源记录。
- 保留未改善、未选点、失败和不确定结果。方法结论从原始报告引用，停止条件与新的运行清单在所属方案维护。

报告指标与对照要求统一见[对照规范](../../experiments/plans/reference/对照规范.md)和[报告核对](../../experiments/plans/reference/报告核对.md)。
