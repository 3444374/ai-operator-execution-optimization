## 当前默认与选择顺序

| 要选择的行为 | 当前树源码默认 | 可选入口及含义 |
|---|---|---|
| 普通文本 Filter records 的模型提交 | `profile=None`解析为`mode="sync"` | `create_records_core(..., profile=...)`可显式选`async`；不因此变成多算子记录级链 |
| 有限多算子链的推进粒度 | `execution="fused"` | `record_local_sections`允许合法记录的后继继续推进；Extract仍保留完整关系屏障 |
| 请求数窗口是否运行时调整 | 固定；`admission=None` | 普通records可显式选两种动态profile；当前完整链owner没有`profile`／`admission`参数 |
| 链的就绪任务次序 | `ready_order="fifo"` | 可选`round_robin`或带明确参数的`successor_first`；通用MethodDriver自身默认轮转，不能混用默认口径 |
| 链的token在途限流 | `token_budget=None`，关闭 | 显式`ChainTokenBudget`启用W安全上限；不是按token组成提交批次 |
| 每批token B组批 | `prepared_batching=None`，关闭 | 同步fused C1单Filter／Map或固定并发异步记录链，支持无每批行帽的token模式；同步受逻辑字节额度，异步另受成员R约束。见[同步接口](../code/src/execution_provider/adapters/README.md#prepared-request-batching)和[异步接口](../code/src/execution_provider/adapters/README.md#optional-async-record-token-batches)；与W不同 |
| worker审计副本提前释放 | `release_completed_audit=False` | 仅共享fused链worker支持；记录级明确拒绝 |
| PG Ray Map的物化／准备 | `payload_backend="daft"`、`preparation=None` | 可选Arrow物化、准备分段、调用方拥有的HTTP worker池；各有独立条件 |
| Animals Q7图像URI保留 | `media_retention_bytes=0`，关闭 | 仅显式Q7及完整媒体身份配置；不等于模型结果／KV缓存 |

先选实际前端和执行路径，再选容量、生命周期和待比较的一个策略。研究优先验证记录级推进，不表示以上全局默认已改变。
固定行数、固定并发、动态并发、token组批和token限流是不同选择，不能只看“async”或“token”字样判断行为。

## 普通文本 records：同步、异步与动态策略

源码：[Core工厂及profile解析](../code/src/execution_provider/adapters/lotus_records_core.py)、[反馈配置](../code/src/scheduling/submission_control/adaptive.py)。
Python工厂为`create_records_core(method, engine, generation, resources, profile=None, async_limits=None, prepared_batching=None, batch_concurrency=None)`，后四项为关键字参数。
普通Movie配置用`core_profile`；resident session／维护plan用`profile`。这是配置字段差别，不是两套算法。
普通Movie的`backend="semloom-local-model-core"`默认同步；兼容入口`"semloom-local-model-core-async"`显式选择异步。
切换后端名仍须提供合法资源，不能通过别名绕过profile／IPC容量检查。

| 准确参数／值 | 默认 | 作用、何时考虑使用 | 约束与效果 |
|---|---|---|---|
| `profile.mode`: `sync`／`async` | `sync` | 同步模型核每次完整返回；异步owner支持多个独立最终结果在途，适合检查持续供给 | 两者都要求prepare/model批行数为1；异步不自动调窗。[E1](#e1)不是普通单Filter入口的通用加速证据 |
| `profile.max_inflight` | `resources.max_active_batches` | 显式固定当前查询请求数上限C | 正整数且不超过声明的请求额度；async的C与引擎每轮`max_num_seqs`分开，仍受原Core／actor／IPC及字节结果额度保护。`"auto"`须显式async，仅取声明请求额度，不做性能搜索 |
| `profile.stage_timing` | `False` | 需要定位准备、提交、等待和收集时开启计时 | 有观测成本；不提供GPU内部瓶颈判定 |
| `profile.admission` | `None` | 显式`{"kind":"resource_feedback", ...}`启用反馈；需要检查压力保护或有限探索时使用 | 只支持async；未传入就不创建该反馈采样任务，不自动启用W或B |
| `profile="delivered-work-scan"` | 不启用 | 原cfdc策略，以已交付请求及输入／输出工作量比较 | 已接main，原参数及当前单轮见[E2](#e2)；不是仅改一个`max_inflight` |
| `profile="computed-work-local-pairs"` | 不启用 | 原ee39策略，用实际计算／缓存token和局部配对比较 | 要有有效原生缓存计数；缺失保持未知。当前单轮及历史负结果分别保留，见[E2](#e2) |
| `async_limits` | `None`，由owner构造 | 高级Python／普通Movie配置中限定IPC输入、结果、命令及控制槽 | 必须与owner上界匹配；不能只覆盖动态初始窗口。详见[容量](#budgets) |

普通records启用token B时须显式固定async、无admission且`stage_timing=False`；组批字段、isolated限制和命令见[Movie入口](../code/src/experiments/movie_matrix.README.md#record-token-batch-entry)。不与动态profile叠加。

两种具名profile展开为：async、初值8、`stage_timing=True`，并显式保留下表“具名profile”的legacy实验参数；不是当前通用默认或最优推荐。
`gpu_ids`在admission字典中默认空序列，若提供须为实际分配的物理GPU UUID；不在公共配置中写现场标识。

| `profile.admission`字段 | `ResourceFeedbackConfig`默认 | 具名profile设置 | 含义与组合条件 |
|---|---|---|---|
| `poll_interval_s` | 0.25 | 0.1 | 反馈读取间隔；缺失／过期反馈不解释为零压力 |
| `window_s` | 1.0 | 0.25 | 测量窗口，秒 |
| `min_samples` | 16 | 16 | 一次有效判断至少需要的样本数 |
| `min_remaining` | 0 | 64 | 正值显式启用旧尾段／未来收益门；0不按剩余条数截断，任务耗尽不证明平台 |
| `exploration_s` | `None` | 10.0 | 正值显式限定探索时间；探索请求正常贡献查询，截止只表示证据截断 |
| `max_changes` | `None` | 8 | 正值显式限定调窗次数；未确认平台时仍报告证据不足 |
| `allow_exploration` | `False` | `True` | False可只保留压力保护；True才允许性能探索 |
| `min_gain` | 0.03 | 0.03 | 候选收益判断阈值，不是已证明收益 |
| `memory_floor_bytes` | 0 | 0 | 原资源压力门；0不是已校准物理显存保证 |
| `search_mode` | `"local"` | `"geometric"` | 本地或几何候选搜索 |
| `work_tolerance` | 0.03 | 0.03 | 工作量比较容差 |
| `max_candidate_attempts` | 2 | 2 | 每个候选尝试上限，支持1～4 |
| `work_basis` | `"delivered"` | delivered／computed | computed要求geometric及实际原生计算工作量 |
| `work_comparison` | `"envelope"` | envelope／local_pairs | local_pairs只允许computed；不是任意字典组合都合法 |

具名profile不替调用方配置资源：原实验另声明C64、CPU准备2、prepare/model均1、相同模型、输入、生成与缓存条件。
修改这些外部条件就不再是原参数复现；当前小样结果不能给其它机器或任务推荐C64。

## 有限算子链：fused、记录级、后继选择与W

入口：[SemLoomRecordChainCore](../code/src/execution_provider/adapters/lotus_record_chain_core.py)。这是Python API；
PR73的四case CLI只是固定16行M→M→F验收入口，不是任意链的自动选参器或完整SemBench运行器。

| 准确参数 | 默认 | 作用／开启时机 | 约束与已有证据 |
|---|---|---|---|
| `execution` | `"fused"` | `record_local_sections`在必要前驱已成功解析后推进该记录后继；用于检验跨阶段等待 | fused要求`cpu_workers=max_active_batches=1`；record要求两个batch rows都1。Extract仍完整装配。有限功能见[E1](#e1)、[E3](#e3) |
| `ready_order` | `"fifo"` | `round_robin`轮转；`successor_first`在源任务与后继同时就绪时偏向后继 | 自定义ready仅同部署同角色F/M，拒绝fused、Extract及角色切换；已在Core中的任务不被此项重新排序 |
| `successor_first` | `None` | 选择后继优先时提供`SuccessorFirst(max_burst, max_wait_s)` | 两字段均须显式正值；连续后继次数和最大等待限制偏向。新192次未触发竞争，不能宣称策略收益；旧两轮变慢见[E4](#e4) |
| `ready_clock`／`on_ready_event` | `None`／`None` | 高级诊断：提供就绪时钟／观察回调，保留实际就绪和选择事件 | 必须可调用；不是独立性能策略或硬件事件。不要为了诊断更换业务语义 |
| `token_budget` | `None` | 显式`ChainTokenBudget(...)`启用在途W，作为防止下游积压的宽松高位安全护栏 | 仅同模型同角色F/M；不支持fused／Extract。W应绑定实际容量，不能把功能测试W134当正常推荐值 |
| `release_completed_audit` | `False` | 成功编码后尽早撤掉worker自己的审计列表引用，适合检查持有寿命 | 仅fused共享worker；Core／Ray／Daft有限链Python入口均有此项。普通Movie单Filter／session不经过该worker；record明确拒绝。只有CPU／组件证据，不证明RSS或完整查询收益 |
| `capacity` | `None` | 按执行模式选CoreChainCapacity或CoreRecordsCapacity；需要明确单项输入／结果空间时指定 | 类型须匹配模式；额度不覆盖全部关系、审计、进程RSS或GPU KV |
| `method_limits` | `None`，由owner推导 | `MethodLimits(input_bytes,state_bytes,result_bytes,stages)`限定记录继续执行时保留的状态 | 仅record；stage数须覆盖完整计划；不是vLLM预算 |
| `prepared_batching` | `None`，关闭 | `PreparedBatching("token_budget", None, B)`按完整输入token＋输出cap组织兼容就绪请求；适合检查不等长记录的供给 | record要求FIFO、`progression="record"`、W关闭，无每批行帽；现有关系屏障保留。已测范围及无冷查询加速结论见[PR84验收](../code/INFRA_STATUS.md#async-record-token-batches) |
| `batch_concurrency` | `None`；启用record组批后解析为1 | 手动固定尚有未结算计算成员的应用传输批数C_batch，不由资源反馈自动选择 | 正整数且不超过成员容量R；仅record token组批接纳。B、C_batch、R分别设置，不能当作vLLM物理批大小 |
| `rolling_refill` | `False` | 本地候选：完成单条即释放请求额度补位，B只组织提交 | 与批并发／批反馈互斥；固定rolling为C_request=R，正常Movie／isolated session可选 |
| `request_feedback` | `None` | 本地候选Python chain选项；正常Movie／session复用`core_profile.admission.kind="resource_feedback"`选择请求级动态rolling | 须rolling且FIFO／record／W关闭；从C_request=1起，R独立保留。固定B，沿现有性能窗口确认；未独审或实机验证，无动态B／快速大步保证，见[入口与默认](../code/src/experiments/movie_matrix.README.md#record-token-batch-entry) |
| `actor_owner`／`control_dir` | `None`／`None` | 高级集成：传入匹配的prepared-only async owner／控制文件目录 | 必须满足原owner身份和关闭责任；不是已支持跨查询模型复用的开关 |

PR84的B=17506、R=259及native128／fixed128使用Movie Q1全量输入长度统计和旧对照条件预设，矩阵`concurrency_search=False`，不是资源反馈自动选参。
token reference生成／统计、预分组、R推导和此前实验成本未计入本轮冷时间；正常查询仍自行准备和计量。数值来源、未找到的64→128决策与计时边界见[PR84范围说明](../code/INFRA_STATUS.md#async-record-token-batches)，不据此声称未知任务零先验自适应。

`LotusRecordChain(..., relation_barriers=False)`是方法合法性选项：非末端／重复Extract须显式True，等待成功EOF、完整结果和关系装配；不能作为“去掉屏障提速”的开关。
chain owner仍不接受普通records的`profile`／`admission`对象；本地动态rolling候选通过上述typed `request_feedback`接入。
普通Movie／session工厂将既有`core_profile.admission`解析为该选项，不改变其他链模式，也不支持其admission cache或resident组合。

W使用[ChainTokenBudget](../code/src/execution_provider/adapters/lotus_chain_token_budget.py)：`active_tokens`必填；
`tokenizer`、匹配的`engine`、`tokenizer_signature`、`template_signature`及每阶段`expected_output`均须明确提供。
`expected_output`的值为`OutputTokenEstimate(tokens, provenance)`，只是显式输出估计；实际W预留始终为“完整chat输入估计＋该阶段生成cap”。
后继使用实际生成列重新准备和计量。单请求超W／上下文容量会拒绝，不自行截断、拆prompt或重试。
取消或unknown本身不释放W；权威终态或既有协议验证的生产者退出证明可结算预留，后者不把unknown结果改为成功。

<a id="budgets"></a>
## 批次、并发、准备和空间预算

这里B指每批累计token目标，W指所有在途请求的token预留总量；C的单位随入口明示，普通异步records按请求，静态批路径按批。历史“B1”常指每次一行，要看原字段。
应用组批、准备批、RPC／IPC包、vLLM计算批和可回收内存块不是同一个批次。

### 文本 records 资源

来源：[RecordsResources](../code/src/semantic_methods/lotus/records.py)。默认构造值不保证能直接用于每种后端；Core要求调用方覆盖batch rows。

| 字段 | 类型默认 | 实际用途与限制 |
|---|---|---|
| `cpu_workers` | 1 | 普通records的准备actor数量；record链由调用方准备，不创建Filter准备actor，增加此数不自动并行格式化；fused须1 |
| `gpu_workers` | 1 | 当前records必须1、TP1；增大不是启用多GPU的方法 |
| `prepare_batch_rows` | 4 | 静态reference准备行数；普通Core和record链必须显式1；fused的准备由共享方法worker拥有，不单独使用该批大小 |
| `model_batch_rows` | 4 | 静态／fused的一组输入行数；普通Core和record链必须1，不是token B |
| `max_active_batches` | 2 | 静态路径为批数；普通Core／未组批record链映射请求数C。record token模式为成员／驻留行R，批并发另由`batch_concurrency`控制；fused须1 |
| `query_timeout_s`／`startup_timeout_s` | 60／120秒 | 查询／启动期限，均须正值；增大只是延长期限，不减少执行量 |

`CoreRecordsCapacity`默认`item_input_bytes=item_result_bytes=2MiB,metadata_bytes=2048,step_actions=16,poll_interval_s=0.01`。
`CoreChainCapacity`相同，但`item_result_bytes=8MiB`；这是一整个fused任务的结果预算。
普通Core高级`evaluate(..., max_inflight=None)`可在现有async owner声明上限内逐查询指定C，前一查询必须结束并结清；不会热扩容actor／IPC／模型。

### 异步IPC和方法状态

来源：[AsyncEngineLimits](../code/src/serving/backends/vllm_async_engine.py)、[actor组装](../code/src/execution_provider/adapters/lotus_records_async_actor.py)。
直接构造的默认：`max_inflight=8`、`result_slots=8`、`command_slots=8`、`control_slots=16`；
`input_bytes=result_bytes=16MiB`、`item_input_bytes=item_result_bytes=2MiB`、`control_frame_bytes=64KiB`、`feedback_interval_s=0.0`。
但owner在未传`async_limits`时按声明C生成：max_inflight/result_slots/command_slots均C、输入／结果总量均C×2MiB、control_slots为max(16,2C)。
显式limits须匹配owner上界并容纳每请求结果；有动态反馈时，反馈间隔由已验证admission配置接线。它们是交接／保留空间，不是GPU显存分区。
默认`method_limits`从item容量及阶段数推导；状态不足会拒绝，不能靠只放大C绕过状态容量。

### 模型引擎声明

来源：[EngineSpec／GenerationSpec](../code/src/serving/backends/vllm_engine.py)。

| EngineSpec字段 | 默认 | 用途及何时改 |
|---|---|---|
| `max_model_len` | 4096 | 上下文容量；与完整输入＋输出cap核对 |
| `max_num_seqs` | 8 | vLLM原生调度的序列容量；不等于应用C_batch或成员R，也不是自动测得最优并发 |
| `max_num_batched_tokens` | 4096 | 交给vLLM内部调度的token预算；不是SemLoom每批B或在途W |
| `gpu_memory_utilization` | 0.8 | 引擎的GPU内存比例；不等于外层W的物理内存保证 |
| `dtype`／`seed` | `bfloat16`／0 | 数值／随机配置，变化须重新核对结果和测量身份 |
| `tokenizer_path`／`chat_template` | `None`／`None` | 可显式锁定本地tokenizer／模板；需与W估计身份一致 |
| `max_model_calls` | `None` | 原生调用总量安全上限，不是并发；运行预算仍须单独记录 |
| `enable_mfu_metrics` | `False` | 可选MFU观测；缺测保持不可用，GPU busy不替代MFU |

`model_path/model_python/driver_python`必填，使用本地模型及隔离解释器；不是优化旋钮。
生成默认为`max_tokens=8, temperature=0, top_p=1, seed=None, stop=("\n",), presence_penalty=0, frequency_penalty=0, repetition_penalty=1, logprobs=None, response_format=None`。
这些属于任务语义。不能为了变快缩短输出、换模型／模板或改parser后仍称纯执行优化；具体算子可声明不同生成配置。

<a id="reuse"></a>
## 模型、参数缓存与数据复用

| 选择 | 默认／入口 | 何时用、真实支持范围 | 证据／限制 |
|---|---|---|---|
| 普通records resident session | 显式[Movie session](../code/src/experiments/movie_records_session.py)；不是全局布尔开关 | 同一个普通Core owner顺序执行首次／复用查询，保留模型；每查询LM缓存仍关闭 | [E2](#e2)有模型常驻与参数提示复用；同模型UID不证明KV／prefix命中 |

| `IncreasingSearch` | 不传则有限候选；`growth=2,min_improvement=0.03,confirmations=2` | 显式声明`parameter/capacity_limits`，可另给`resource_limits`；按预算递增找局部平台 | `calibrate`默认`repetitions=3,near_peak_ratio=0.97,work_per_sample=1,stop_on_failure=False`；真实回调、`ScanBudget(timeout_s,max_work)`须明确。容量边界不是最优点 |
| PG HTTP worker复用 | `RayMapConfig.worker_pool=None` | 调用方先用`owned_map_worker_pool(...)`创建服务并保持Ray连接，再独占借用匹配worker | 复用的是HTTP worker，不是把vLLM搬进该actor。[E5](#e5)有特定部署改善 |

## PG／完整HTTP请求路径

本节适用于PG SemMap及完整请求adapter，不能把字段直接放进LOTUS record链构造器。
入口：[gateway CLI](../code/src/execution_provider/server.py)、[组装函数](../code/src/execution_provider/adapters/incremental_execution.py)、[RayMapConfig](../code/src/execution_provider/adapters/ray_map_transport.py)。

| 参数 | 默认 | 作用／何时用 | 约束及效果 |
|---|---|---|---|
| `--incremental-map` | False | 启用v6增量Map；PG对应`provider_execution_profile='incremental-map'` | 支持形状、取消和输入窗口按extension；不是任意SQL多在途 |
| `--max-active-requests`／`--max-held-tasks` | 1／跟请求容量 | 执行C／已接纳任务数；后者可大于C以保留有限候选 | 不能靠增加连接数扩大执行容量 |
| `--input-buffer-bytes`／`--result-buffer-bytes` | 未指定；按单项上限×held推导 | 限输入及结果预留，慢消费时施加背压 | PG单项输入和模型响应默认各1MiB；不是进程RSS总限额 |
| `--max-active-jobs`／`--max-connections` | 1／8 | 同Engine内Job数／连接数 | 多Job须增量路径；存储必须让每Job容纳合法任务 |
| `--job-compute-policy` | `equal-share` | `shared`允许各Job使用空闲计算容量，存储仍各自预留 | 仅支持的增量组装；不是DRR/VTC／多租户份额方案 |
| `--frame-timeout-ms` | 120000 | wire帧超时；固定HTTP配置另有`timeout_ms` | 不把每次模型HTTP超时自动当整查询排队期限 |
| `--organization-config` | 不传 | 显式PG单Job Map的rows／work／length组织 | 与Ray Map自有factory不能同时选，见下表 |
| `--map-transport-config` | 不传 | 显式Daft／Arrow载荷＋Ray HTTP worker传输 | 需fixed-model incremental Map，拒绝同时传organization配置 |

`RayMapConfig`必填`address,workers,batch_rows,window_bytes,object_bytes`，没有通用数值默认；address必须为显式已存在集群，不接受`auto/local`。

| RayMapConfig字段 | 默认 | 作用／组合及何时用 |
|---|---|---|
| `workers`／`batch_rows` | 必填 | HTTP actor数／每载荷批最大行数；worker并发与Core请求容量共同约束，不是GPU批大小 |
| `window_bytes`／`object_bytes` | 必填 | 有限传输窗口／Ray对象额度；object至少window+8字节，并须装下合法请求及准备空间 |
| `worker_pool` | `None` | 如需跨查询借用已创建的匹配HTTP服务，显式填服务身份；调用方拥有创建／关闭责任 |
| `payload_backend` | `"daft"` | 可选`"arrow"`直接物化；特定PG内部对照小幅改善，见[E5](#e5) |
| `preparation` | `None` | 显式`StageBrokerLimits`分离准备借用；适合机制诊断 |
| `coalesce_queued_preparation` | `False` | 只在preparation已启用时，追加同归属尚未开始准备的队尾块；不等候未来行 |
| `response_mode` | `"completion"` | `full`保留完整HTTP响应；native builder自动选full，池身份须匹配 |

`StageBrokerLimits`的`encoded_bytes,ready_bytes,ready_work,prepare_inflight,model_inflight`全部必填正值；
PG Map当前要求prepare_inflight=1且ready_bytes不超过对象额度。它们按阶段表示／租约计费，不覆盖源全集、所有副本、最终消费者或GPU KV。
准备分段及尾块追加已有真实负结果，见[E5](#e5)，不作为默认推荐。

PG Map组织配置[MapOrganizationConfig](../code/src/execution_provider/adapters/map_organization.py)字段均必填：

| 字段 | 可选值／作用 |
|---|---|
| `mode` | `rows`输入序行数组；`work`输入序累计token work；`length`在有限候选前缀按work升序 |
| `window_rows`／`batch_rows` | 候选前缀／组行数上限；batch≤window≤256，且window不超过held任务容量 |
| `batch_work`／`active_work` | 每组目标／在途总上限；work按完整输入token＋输出cap计算；大于分组目标的完整单行独占一组 |
| `model_id,model_revision,serving_revision` | 模型／服务身份，不能只写别名假装相同 |
| `tokenizer_path,tokenizer_sha256,context_tokens` | 本地分词器、内容指纹与上下文；超context拒绝，不截断；active_work至少context |

这是已接PG单Job Map v6的组织，不是尚缺的LOTUS链token B接线。组仍展开为独立请求，不插入整组完成等待；分组标签相异也可能没有实际提交差异。
不支持Filter/query-job、原生Ray/LOTUS或与上述自有Ray传输factory叠加；信息获取、tokenizer常驻内存和准备成本计入评价。

| 入口 | 默认与范围 | 含义／限制 |
|---|---|---|

## 配置片段

以下只展示准确字段，嵌入已有合法模型、方法和资源配置；不代表最佳数值，也不会自动启动任务。

普通records固定异步（Python）：

```python
from src.semantic_methods.lotus.records import RecordsResources
from src.execution_provider.adapters.lotus_records_core import create_records_core

# C=4只是示例，engine.max_num_seqs必须至少4。
resources = RecordsResources(cpu_workers=1, gpu_workers=1,
    prepare_batch_rows=1, model_batch_rows=1, max_active_batches=4)
owner = create_records_core(method, engine, generation, resources,
    profile={"mode": "async", "max_inflight": 4})
```

两种动态策略在普通Movie JSON中分别选择，session将键名换为`profile`；其它必需字段沿用现有完整配置：

```json
{"core_profile": "delivered-work-scan"}
```

```json
{"core_profile": "computed-work-local-pairs"}
```

它们的历史初值为8，故示例C4资源不能直接与这两个名字拼接；须显式提供能容纳初值及owner上界的真实资源，原实验声明为64。

记录级链的固定FIFO/count（Python；同一模型部署）：

```python
from src.execution_provider.adapters.lotus_record_chain_core import SemLoomRecordChainCore

owner = SemLoomRecordChainCore(engine, resources,
    execution="record_local_sections", token_budget=None, ready_order="fifo")
```

仅在同模型同角色F/M计划中单独试后继优先：

```python
from src.semantic_methods.driver import SuccessorFirst

owner = SemLoomRecordChainCore(engine, resources,
    execution="record_local_sections", ready_order="successor_first",
    successor_first=SuccessorFirst(max_burst=2, max_wait_s=1.0))
```

开启W时先以已锁定tokenizer／模板／模型构造预算；`W`取实际容量下的安全护栏，不照搬134：

```python
from src.execution_provider.adapters.lotus_chain_token_budget import ChainTokenBudget, OutputTokenEstimate

budget = ChainTokenBudget(tokenizer, engine, active_tokens=W,
    tokenizer_signature=tokenizer_sha256, template_signature=template_sha256,
    expected_output={stage.stage_id: OutputTokenEstimate(
        stage.generation.max_tokens, "declared generation cap; not measured output")
        for stage in chain.stages})
owner = SemLoomRecordChainCore(engine, resources,
    execution="record_local_sections", token_budget=budget)
```

PG已有RayMap JSON中只替换物化方式的片段：`{"payload_backend":"arrow"}`；
须嵌入完整RayMapConfig，不能同时添加`--organization-config`。图像已有Q7配置可显式选择`--media-retention-bytes`，Q1不接受；不提供伪造模型／媒体身份示例。
