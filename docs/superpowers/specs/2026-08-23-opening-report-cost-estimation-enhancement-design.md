# 开题报告中代价估计与两项研究内容的关系调整设计

## 目标

在不改变“两项研究内容”结构的前提下，明确三层关系：

1. 数据组织本身研究数据库记录怎样形成适合 AI 执行的批次；
2. 提交与多作业调度本身研究在 GPU 数量、模型服务实例数及每个实例可承载的请求数和工作量有限时，怎样安排尚未提交的工作；
3. AI 算子代价估计既服务数据库计划优化和多 SQL 安排，也可以作为额外信息增强前两项研究，但不是前两项研究成立或运行的必要条件。

## 一句话论证

本课题先使用运行前可直接获得的工作特征、预先测得的模型服务能力和执行过程中采集的实际状态，分别研究数据组织与多作业调度；再检验预计执行时间、预计剩余工作量等代价信息能否在这些基础方法上带来额外收益，同时研究这些信息对数据库执行计划比较的作用。

## 术语约定

| 术语 | 本报告中的含义 |
|---|---|
| 工作描述（WorkDescriptor） | 保存记录身份、作业身份、分阶段工作特征和数据局部性等运行前已知信息，不包含必须由代价模型预测的字段 |
| 基础数据组织方法 | 直接依据词元规模、图像大小、共享前缀、批次工作量上限等已知特征形成批次 |
| 基础调度方法 | 依据预先测得的每个服务实例可承载的请求数和工作量上限、完成通知及实际运行状态，安排请求提交、作业选择和服务实例选择 |
| 代价信息增强方法 | 在相同基础方法上增加预计执行时间、预计资源需求、预计剩余工作量或估计区间，并检验这些信息是否改善结果 |
| AI 算子代价估计 | 将工作描述和历史测量换算为预计成本的组件；数据库优化器或调度模块作出最终决定 |

## 章节调整

### 2.4 当前研究存在的问题

- 数据组织问题先说明数据库和数据框架常用记录数、字节数、分区或固定批次描述数据规模，模型服务的连续批处理只处理已经到达的请求。这些做法没有直接回答数据库记录在到达模型服务前怎样按 AI 处理需求形成批次。
- 调度问题先说明固定并发、静态份额、独立作业提交和模型服务内部调度各自解决什么问题，再说明它们没有同时利用数据库作业进度与模型服务实际排队、运行和完成情况。
- 代价估计作为补充问题出现，不把前两项问题写成依赖预测结果才能解决。

### 3.2.1 分阶段工作量表征与数据组织

段落顺序调整为：

1. 常见做法及其作用；
2. 固定行数或固定批次不能表示 AI 工作量的原因；
3. 本课题研究的工作描述、批次工作量、均衡与数据局部性；
4. 基础方法使用直接可知特征；
5. 代价估计只作为可选增强，将工作特征换算为预计时间后参与组批；
6. 基础方法和增强方法在相同后续调度条件下分别评价。

主要引用使用 Ray Data Streaming Batch、Daft/Arrow 数据执行、Orca/vLLM 连续批处理和局部性感知服务调度等已有文献及官方资料，不新增未经核验的参考文献。

### 3.2.2 固定容量下的提交、路由与多作业调度

段落顺序调整为：

1. 常见的固定并发、静态作业份额、独立提交和服务端内部调度；
2. 空闲份额不能及时使用、配置上限不能代表实际状态、多作业相互影响等不足；
3. 本课题研究尚未提交工作的提交时机、作业选择和服务实例选择；
4. 基础方法使用容量测量、完成通知和运行状态；
5. 代价估计只作为可选增强，为预计服务时间或剩余工作量提供参考；
6. 评价总体效率、作业完成时间、尾延迟和作业之间的服务差异。

主要引用使用 Ray、vLLM、VTC、FairServe、Themis、Tiresias、Pollux 等已有文献，明确这些工作分别位于通用分布式执行、模型服务或集群调度层。

### 3.2.3 AI 算子代价信息与跨模态验证

- 保留数据库内核优化器用途：比较关系算子与 AI 算子的执行安排，以及多条 SQL 的执行顺序和并发方式。
- 增加对研究内容一的增强用途：把工作特征换算为预计批次执行时间或资源需求，辅助比较候选组批方式。
- 增加对研究内容二的增强用途：提供预计服务时间和剩余工作量，辅助作业选择与服务实例选择。
- 明确两项研究内容的基础方法可独立运行，代价信息是否采用由对照实验决定。

### 4.1 研究方案

- 数据组织实验先比较不使用代价预测的候选方法，再在相同条件下加入代价信息，检查是否产生额外收益。
- 调度实验先比较只使用容量、完成通知和实际状态的方法，再增加预计服务时间或剩余工作量。
- 数据库优化实验独立构造结果含义相同的候选 SQL 执行计划和多 SQL 运行清单。
- 不把“预测更准确”直接写成“系统一定更快”，最终以实际执行结果评价。

### 4.2.5 前期实验

保留 429 条运行记录、六种方法、四种在途工作量上限和当前数值。补充一句：现有实验是离线代价估计验证，尚未把预测结果接入数据组织、多作业调度或完整数据库优化器，因此不能作为增强方法已经有效的证据。

### 第五、六部分

- 进度安排先完成两项基础方法的独立评价，再进行代价信息增强对照。
- 预期成果先列两项基础研究成果，再说明轻量代价估计组件可用于数据库计划优化，并可接入前两项方法进行增强实验。

## 证据与表述范围

- 已有数据组织实验可以说明固定行数、工作量组织和局部性在不同服务压力下表现不同，不能说明一种方法普遍最好。
- 已有多作业实验可以说明静态分区与共享方法存在效率和作业体验之间的取舍，不能说明状态驱动方法已经全面胜出。
- 已有代价估计实验只支持在当前文本环境下区分四种外部执行参数的初步能力，不支持数据库优化器、数据组织或多作业调度已经因预测而改善。
