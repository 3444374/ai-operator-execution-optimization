# 数据就绪后的 SQL／原生 API 与统一 HTTP 计时

本报告对应[SQL就绪计时方案](../../../plans/SQL就绪计时.md)，补充同应用完整查询比较。
原始数据、连接和可复用组件先准备，记录实际 SQL／API 入口到统一消费端读完结果的耗时。
它不能由旧完整应用耗时减去准备估计得到，也不用于证明纯调度优势。

## 计时与执行归属

| 路径 | 提交前完成 | 计时内执行 |
|---|---|---|
| PG＋SemLoom 本地 HTTP及三控制 | PG输入表、连接、语义配置、网关与cursor | 原生SELECT、查询特有work估算与组织、模型调用、结果消费 |
| LOTUS Map | 原始DataFrame、tokenizer和LM配置 | 原生`sem_map`提示装配、执行及结果消费 |
| DuckDB社区AI | 连接、ai扩展、配置与原始影评表 | SELECT内装配相同提示，`ai_try_complete`、`fetchall`及统一消费 |
| Daft prompt | Native runner、provider与原始DataFrame | 原生字符串表达式、`prompt`查询图与结果消费 |
| Sema | 作者二进制进程、配置、CSV导入、输入数量核对 | 原生语义SELECT、结果读取与普通SQL完成标记 |

查询耗时为`(t_query_terminal_ns-t_submit_ns)/1e9`；EOF表示消费端读到结果结束。
准备入口到同一EOF保留为完整应用耗时；运行组件就绪到提交之间的记录器准备另列。
首行和每行时间分别保留，记录写盘与资源关闭在EOF后另计。原`execution.json`不重写，
新时刻写入`ready-timing.json`并记录原文件SHA-256，摘要可同时读取两类信息。

HTTP代理对各路径记录同一单调时钟：代理收到请求至本地`write_eof`写出返回，以及实际转发至完整上游响应。
该区间不含SDK此前排队、客户端接收及解析，写出不代表客户端确认收到。PG计账在代理之前，
原生系统计账在代理发送前；上游区间排除两种计账位置，完整代理区间保留各自实际成本。
不能把代理HTTP区间、批量单行交付和整条查询混为一个端到端分布。

所有系统保留原生提示、解析、并发和调度。DuckDB保留整批`fetchall`，Sema完成标记成本计入查询；
Daft每个新driver设置一次Native线程，可在同一prepared对象上重复execute，不能在同进程反复设置线程数。
PG本地HTTP为内部参照；本次没有测SemLoom Daft／Ray主执行路径。

## 验证与失败保存

本地102项相关检查、服务器实际aiohttp版本的12项网络检查通过。新回归覆盖实际提交、部分结果、
原生取消、停止后拒绝转发、预算／时刻／cursor／summary清理错误不覆盖首错。旧默认应用入口继续使用原分支。
LOTUS／Daft／DuckDB实际库证明准备零HTTP、旧新完整请求一致和重复执行；Sema作者二进制证明持续SQL会话、
准备零HTTP、行关联和错误／消费者取消回收。所有这些检查为CPU／假HTTP，不作为真实模型性能。

八路径真实PG＋假HTTP的前四次失败分别来自binary账户权限、假服务token使用不符、假tokenizer并发借用、
假服务未处理原生OpenAI文本片段。全部保留；修正测试环境或假服务后另记新身份，没有改提示、调度或放宽检查。
随后`ready-cpu05`与最终源码`ready-cpu06`各8条查询／16次假HTTP通过；后者独立核对进程、PG、端口、ACL和GPU0清理。

Sema作者binary未暴露可关闭原生重试的设置。错误探针观察到重复提交，统一代理在首错后取消自有进程，
后续请求拒绝转发，不把退出码0视为模型成功。查询超时停止后续转发，并调用可用取消接口；
没有安全中断接口的原生API还由SDK请求期限和外层140秒单元进程监督处理。

## 分支整合

就绪计时入口已接入语义系统比较分支，三处重叠修改同时保留原始响应字节、真实上游状态／用量和首个错误。
273项本地检查通过：195项文本baseline、14项HTTP观察器和64项查询／记录器检查，均为fixture；
[整合核验](raw/integration-verification.json)保存本地环境、15份接入源码／测试摘要与两组证据的恢复结果。
组合回归确认损坏响应先保存字节，再取消原生执行并拒绝继续转发。真实数据仍对应`ready-source04`；
整合修订单独记录本地验证，新增模型请求0。
