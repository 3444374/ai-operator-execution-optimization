# worker复用后的真实文本Map耗时

2026-09-30开始准备，2026-10-01完成最后测量。对应[准备调优计划](../../../plans/text_map_preparation_tuning.md)。
研究对象为 PostgreSQL 内置 AI 语义算子的外部分布式物理执行与调度优化。

最后一个服务运行中29条查询、20,624次真实POST全部通过，用时606.337秒；之前64次16行检查不重放，
累计20,688次。1024行五种身份各一次预热、三次交错测量，全部性能重复来自最后同一服务运行。
worker复用使本次SemLoom完整查询中位数16.502→14.794秒，减少10.35%，准备4.737→2.831秒，减少40.24%。
仍慢于direct与Daft，不支持通用执行优势；原始失败和质量差异保留。

执行源码为`36669bc0`的独立快照，817份文件运行前后逐项SHA一致；本轮没有修改执行层代码。
PG18.3及现有extension摘要重新核对，driver Python3.12.3、Ray2.56.1（源码commit
`06729817574615e25afe8f20902b37660c2e6962`）、Daft0.7.21、Arrow24.0.0、vLLM0.25.1。
Qwen2.5-7B-Instruct公开revision `a09a35458c702b33eeacc393d103063234e8bc28`的9份文件重新核对。
GPU编号0单卡，bfloat16精度、张量并行份数1、模型长度4096、显存比例0.8、FCFS（先到先服务）、128序列/8192批次token，
prefix caching关闭、chunked prefill开启，generation config为vLLM；实际服务命令与进程记录在归档中。
模型就绪前191.498秒、共享Ray启动9.866秒均另计。

沿用旧16行correctness及已使用的1024行评价输入，SHA分别为
`c169ff3a7fffb67f4a126d703f61147b1e3efaded15ac4dc6711ed6dba7814f4`、
`4e4d7872d239000d4cc631be3c91f711f5a7febbdb5c13c3801d5543fdb27250`。
输入重新校验并安装独立临时PG表；1024行属于固定配置复测，不是新的未使用评价集。
参数沿用[旧四路径选点](../text_map_main_real_20260930/README.md)，不按本轮结果重新选择。

模型、PG、Ray及worker服务在查询前就绪，每查询新driver/gateway与执行图。
共享Ray共8个逻辑CPU、256MiB对象存储、0GPU；常驻SemLoom actor保留1个CPU名额，baseline期间空闲，
初始可用7个名额。原生Ray4个HTTP actor、读取并发2，其他图阶段由Ray分配；CPU没有物理隔离。
因此这是本次共用部署和混合worker生命周期的实测，不表示各框架都独占8个可用名额。
原生Ray/Daft仍拥有自己的读取、批次、并行与backpressure；没有加入SemLoom提交策略。

SemLoom两臂C64、PG窗口256、1个worker、16行批次、2MiB传输窗口与4MiB对象额度；
direct C64，Daft C64/8线程/4读取分区，Ray C128/4actor×32异步批次/单行batch/4读取块。
在正式1024行重复前，旧SemLoom另做8条16行准备查询，记录消耗预启动worker后的行为。

## 中止、修订与清理

首次控制器数据库环境名称不一致，模型POST0且没有请求账本；修订接线后，原时限内继续准备。
direct、Daft、Ray的16行检查成功，共48次；检查器将原生Ray常驻观测actor误判为查询残留，停止。
按[实际版本源码](https://github.com/ray-project/ray/blob/06729817574615e25afe8f20902b37660c2e6962/python/ray/data/_internal/stats.py)
及无模型复现核对，它们是0CPU的detached服务，查询worker已结束、CPU8归还。
修订只识别已核对的服务类/名称与detached身份，未知actor仍导致停止，没有修改Ray或baseline图。

用户明确授权余20,640次后，旧SemLoom16行检查成功；保存原始Ray状态遇到protobuf
`ActorDeathCause`无法JSON序列化，记录器退出。累计64次。修订为明确保存可序列化身份/状态字段，
两项检查及真实Ray元数据的无模型保存验证通过；用户再次确认余29条、20,624次和25分钟时限后才继续。
64次没有退款或重放，前面三个控制器保持`failed`，最后控制器为`passed`。
全部错误、修订前控制器和有效16行子查询保留在归档中；这是实验控制器问题，不改写旧真实模型故障结论。

目标环境原有89项相关检查全部通过，另有2项记录器检查与无模型Ray复现。
[最终清理](raw/cleanup.json)核对126个查询摘要中的PID及创建时间，活动残留0；
四个模型进程组正常退出、无强制结束，PG/Ray/HTTP已停止，父目录ACL恢复原值，GPU计算进程为空。
