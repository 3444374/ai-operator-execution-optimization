# 已选payload的Daft与直接Arrow分批对照

2026-10-02。按[准备调优计划](../../../plans/text_map_preparation_tuning.md#热路径独立计时与无模型验证)，
继续定位 PostgreSQL 内置 AI 语义算子的外部分布式物理执行与调度优化中的传输开销。
用户要求负优化暂不采用；本轮两臂均使用同步持久记账，不启用前轮变慢的线程记账。
**完整查询中位数8.354→8.149秒，减少2.457%；仅为无模型小幅观察，默认Daft保留。**
10条查询、8,224次fixture全部通过，真实模型请求0，耗时103.680秒并完成独立资源核对。

## 实现与资格

执行源码`f89ba28a77857a59d7f698910b61efe95b549387`，821份源码摘要与干净受控文件状态核对通过。
`RayMapConfig.payload_backend=arrow`直接把Core已选好的有限行构成Arrow批次，不再为该窗口创建Daft图。
全部行身份及字节先核对，再按同一行数上限输出；各批次使用独立缓冲，保留large-binary字节、顺序和提前关闭。
旧`daft`及默认方式保留，选行、请求正文、模型、持久事务、取消和未知远端计费保持原行为。
查询配置`map_payload_backend`必须与物理文件一致；Arrow/Ray独立标识，不能进入原`pg-daft-ray`比较。

新参数的最小验证修改前复现2个错误，修改后通过。本地相关86项中74项通过、12项缺Daft/Arrow跳过；
目标环境92项全部通过，包含二进制文本/图像/空字节、跨session身份、重复值、尾批、提前关闭、独立缓冲，
以及两种分批的取消、未知结果、对象额度、旧同步/HTTP与比较读取。原PG库摘要
`38370204a7d487f24b7a10d2f452f9ea1502b0e8be7dc6587789c0d9ca83186d`保持，未重建数据库软件。

## 条件与完整时间

PG18.3、Ray2.56.1、Daft0.7.21、Arrow24.0.0、psycopg3.3.4、httpx0.28.1，现成driver未改动。
共享Ray8逻辑CPU、256MiB对象存储、0GPU；两臂各一个服务拥有worker和共享gateway，初始可用6CPU。
C64、PG窗口256、批次最多16行、2MiB输入窗口/4MiB对象额度、相同合成中英文输入和确定性HTTP服务。
Daft8线程、统一退出遥测，无物理CPU隔离。唯一显式变量为分批backend，持久记账均为同步。
每臂先16行检查，再1024行一次预热与三次交错测量；全部属于同一fixture服务和持久账本。
15分钟整体、每查询120秒、清理预留120秒，首次错误即停。fixture的token字段不是推理工作量。

## 减少的开销与剩余等待

| 每1024行，重复1 / 2 / 3 | Daft | Arrow |
|---|---:|---:|
| 有限输入窗口数 | 21 / 23 / 24 | 22 / 22 / 23 |
| Ray对象批次数 | 76 / 75 / 71 | 76 / 76 / 73 |
| 批次next函数执行累计，秒 | 0.980 / 1.015 / 1.014 | 0.203 / 0.216 / 0.196 |
| next结束至事件循环恢复累计，秒 | 5.587 / 5.982 / 6.133 | 6.246 / 6.588 / 6.824 |
| Ray put函数执行累计，秒 | 0.557 / 0.525 / 0.552 | 0.474 / 0.526 / 0.475 |
| 持久reserve函数执行累计，秒 | 5.142 / 5.394 / 5.506 | 5.207 / 5.598 / 5.609 |
| 计费的Arrow底层缓冲峰值，字节 | 50,928 / 50,557 / 50,557 | 17,760 / 17,760 / 17,760 |

事实：批次构建执行累计减少约0.78–0.82秒，但完整查询只减少0.081–0.205秒；批次数和窗口数相近。
源码保持单线程同步记账，构建线程可与记账重叠。构建更早结束后仍须等事件循环处理结果，
与恢复等待增加的记录相符；这解释了局部时间减少不能全部转成查询收益，不逐项相加为完整时间。
next计时是函数进入至退出的墙钟，包含库内等待与线程调度，不是纯CPU处理时间。
reserve仍累计5.14–5.61秒，其进入至退出包含SQL、持久提交和系统等待；各自占比尚未采集。
下一项优先细分这些实际步骤，再决定是否需要另一种记账方式，不因本轮微测重启线程选择。
缓冲峰值为保守记账值，不是进程RSS或Ray整个对象存储实占；本轮对象额度未成为瓶颈。

无HTTP微测独立使用1/2/16/64行窗口、16行批次，导入另计，每项一次预热与三轮20次，合计488次转换。
