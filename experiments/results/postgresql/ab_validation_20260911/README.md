# A/B 查询验证补充（2026-09-11）

受众：内部工程与验证。来源为生产模块、受控时钟/HTTP测试、独立 PostgreSQL 18.3 与固定的
Ray 2.56.1 / LOTUS 1.2.4。研究对象仍为 PostgreSQL 内置 AI 语义算子的外部分布式物理执行与调度优化。
本记录补充 A 的失败记录与 B 的验收入口，不改变旧实验数据，也不重新授予旧结果独立验证资格。

## 修订范围与验证对象

从 `c4354cd6` 开始，核对针对旧 `d9a27ac4` 的用户审查。保留 A 的 offer/progress 修复、C 的总字节
留存及 D 的 token 组织；不修改 PostgreSQL C 源码、Core 调度、模型消息或 LOTUS 原查询/解析器。
审查附件的 11 项外部检查未在本机直接复跑；下面的检查导入本仓库实际模块。

| 问题 | 修订与检查 |
|---|---|
| B 绕过结果完整性入口 | 统一调用 `evaluate_recording`；评分前核对完成状态、行数、字节数和 SHA-256。篡改时间字段也拒绝，缺 SHA 不再作为兼容成功路径 |
| direct/Ray 完成与最终行缺独立关联 | direct 在执行前记录行号/任务 key，并在实际发送处记录 key/attempt；Ray 原生 payload 携带观察身份，由 session 在出站前移除，并绑定实际响应。评分前逐行核对，重复文本不用哈希猜身份 |
| 流建立失败与慢清理 | LOTUS/Ray 的查询工作延迟到迭代；`query_failure_scope` 允许资源拥有者在清理前报告首错。新增流进入时点/阶段；不合作的第三方上下文只能记录其返回异常的时间，不从异常链猜最早时点 |
| 只验最终归零 | 共用 `query_resources` 核对五项责任全部已记录转换的非负性、峰值和上限；有请求却只有最终零值或缺少字段均拒绝。失败单元仍保留已知证据及 unknown |
| direct 先填满再交付 | 一个正在读取的输入、HTTP 任务和未消费结果共享 C；等待可推进事件，慢下一行不阻塞已完成结果，两种顺序均检查取消与清理 |
| Ray 参数与资源范围 | CPU=4、actor=2、对象存储256MiB独立声明，读取并发/批行数与 HTTP 容量另列。采样进程树、CPU时间及已登记PG读取进程；连接建立即保存其RSS，短于采样间隔的峰值保持未知 |
| PG 实际计划与窗口 | 保存查询前同连接/设置的普通 EXPLAIN，并摘要语义节点、窗口和回退原因；无字段则未知，不把 HTTP 配置当有效窗口 |

Ray 的身份封装只发生在观测 adapter，实际模型请求值保持相同；`HttpRequestUDF` 仍由 Ray 创建和
逐行等待原生 POST，没有注入 SemLoom 提交或并发控制。固定版本源码已核对，原生每 actor 一个
异步批次；本轮实际 HTTP 峰值仍由独立事件核算。逻辑 CPU slots 不等于物理独占 CPU。
