### 扩测停止与HTTP读取诊断

`semantic-eight-path-tail-real-20261008`在235.253分钟后按首次错误停止。已完成1,093条测量查询，
另有8条检查及8条预热；五系统各137条，三控制各136条。完整通过的查询对应563,840次模型成功；
持久请求记录共564,150条，服务成功计数564,149。失败查询另登记310条请求、服务成功增量309，
消费端收到246行；这些部分结果保持暂定，不作为完整SQL完成样本。全部原件继续保存，未重放该运行。

失败路径为PG本地HTTP的请求数FIFO、C64、第137轮，任务编号302。实际异常链为
`httpx.ReadError → httpcore.ReadError → anyio.BrokenResourceError → builtins.BrokenPipeError`。
[网关适配](../../../../code/src/execution_provider/adapters/incremental_session.py)将执行失败统一映射为模型不可用，
[PG错误映射](../../../../code/postgres/semloom_pg/src/executor/pg_semantic_runtime.c)再报“模型端点不可用”；
该文字本身不能证明整个模型服务退出。故障时刻与全部310条HTTP开始／结束见
[保留事件](raw/tail-failure/failed-request-events.jsonl.gz)，消费状态见[执行记录](raw/tail-failure/failed-query-execution.json)。

失败HTTP观察区间为961.149毫秒，远未达到30秒请求时限；HTTP错误早于查询结束，显式取消时刻未记录。
该请求开始至发送前登记记录为1.459毫秒，包含校验、持久登记与观察，不是独立SQLite事务时间。
模型日志没有记录错误响应、模型异常或显存不足，模型服务在控制器清理时正常退出；
之后网关清理需要强制退出的错误另保留，发生在读取失败之后。停止后的独立检查显示控制进程退出、GPU0为1MiB／0%。

同一Linux驱动、同一实际HTTP transport的无模型复现分三组、各5次，每次2条本机HTTP请求：

| 情形 | 结果 | 可以说明什么 |
|---|---|---|
| 同一连接的第二条请求被本机服务重置 | 5次均出现`httpx.ReadError` | 连接读取中断能触发实际适配器的同类失败 |
| 同一连接正常返回 | 5次全部通过 | 单纯复用并不必然失败 |
| 每条请求使用新连接 | 5次全部通过 | 本机复现中的连接复用与重置共同触发错误 |

本机注入的底层异常为`ConnectionResetError`，与原始`BrokenPipeError`不同；不能据此认定原始TCP关闭原因。
新增本机HTTP30次，真实模型／PG／GPU调用0，所有探针资源退出。实现见
[复现脚本](raw/tail-failure/run_transport_fixture.py)，各次原值保存在同目录的`reset.json`、`plain.json`、`fresh.json`。

当前客户端使用HTTPX默认5秒连接保存时间，已安装vLLM源码的服务端默认也为5秒；
实际运行的该环境变量值没有完整保存。连接关闭与复用发生竞争是待验证解释，
原记录缺少逐请求连接ID、空闲起止与当时TCP记录，精确触发条件仍为`unavailable`。
