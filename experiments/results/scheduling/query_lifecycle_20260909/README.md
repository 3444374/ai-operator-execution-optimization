# 查询接入的生命周期与连接接纳加固

基线：`25c0f090`。当前状态：受控、PG与真实模型验证通过；主干集成见本页末尾。
本轮为既有查询归属接入的正确性修正，不新增算子种类或研究算法。

## 问题与处理

在隔离的旧提交源码上，以受控backend实际复现：流空闲超过帧期限会关闭查询、standalone/半帧连接
能使已承诺的流加入失败、令牌生成失败会留下Job。该复现使用本地模拟peer身份，不是实际PG/模型实验。

| 基础动作 | 当前负责人及完成含义 |
|---|---|
| 接受、收发、关闭socket | 连接运行时；结束传输不代表模型已结束 |
| 连接名额承诺 | ConnectionCapacity；查询、standalone及未分类入口统一计账 |
| 登记及加入 | QueryRegistry/执行组装；失败自行回滚尚未交付的Job/session |
| 查询与流结束策略 | QueryRegistry接收明确的连接结束事件；正常流结束不关兄弟流 |
| PG节点归属 | runtime持有PgQueryJobFlow，provider只使用句柄；flow_end原语幂等 |
| 任务接纳与权威完成 | 仍由同一个Engine计费、提交与释放，不另建调度器 |

查询控制连接先于算子连接建立。已登记流允许帧间空闲，但首字节开始后仍有帧期限；控制连接收到
任意额外字节即拒绝。总socket上限内保留一个有期限的未分类入口，避免已声明流名额被standalone
消费；入口满时暂不accept。此规则不能保证抵抗无限客户端持续抢占监听队列，不作抗拒绝服务承诺。

## 验证与复现

- Linux：350项调度、50项提供者、116项PG Python、5项观测辅助，共521项通过。
- PG18.3：回归1项、TAP2006项；查询专项43项，包括500ms帧期限下游标暂停1.2秒再取数。
- 新增受控用例检查半帧超时、控制连接额外字节、预留名额竞争、登记/加入发布异常及无遗留资源。
- 直接执行C流结束与runtime关闭函数，验证重复调用不重复计数、另一流仍可结束。
- 真实模型：独立26次POST全部通过，12个Job、16次Filter和10次Map完成。基于原24次工程用例增加游标恢复的一行（Filter+Map）。

模型为已校验的Qwen2.5-7B-Instruct，保持既有单服务配置；654份源码/测试与模型9份文件在运行前核对。
合成输入TRUE，双Filter采用两个相同的明确条件。没有性能对照、消融或自然语言质量实验；
先前非空条件返回UNKNOWN的失败仍保留在[查询归属记录](../query_job_20260909/README.md)，未宣称已修复。

## 结果与后续范围

本轮不实现方法中间状态总预算、不增加choice Filter/Map窗口、更广SQL形状或动态资源借用。
方法状态应由有界方法驱动管理，不能放进gateway。登记、连接、流结束和远端回收的区分可继续复用。
原始材料归档于raw；日志/脚本先脱敏后压缩，真实runtime配置、凭据和查询能力令牌不入库。
