## 改动与实际范围

[SharedClaimedUnit.reserve_many](../../../../code/src/experiments/shared_request_budget.py)接受非空有限摘要列表或元组，
整批核对剩余额度并在一个原有持久事务内写入，提交成功后才返回按输入顺序排列的attempt（计费编号）。
相同摘要仍分别计费；整批不能容纳时全部拒绝，不自动缩小、等待或重试。
原`reserve`保留逐行返回值。账本格式、每次重新连接、`BEGIN IMMEDIATE`与`synchronous=EXTRA`保持。
已提交但未发送、或提交成功后报告错误的记录不退款；提交错误不返回编号，调用方不得发送。
机制依据为[SQLite官方事务说明](https://www.sqlite.org/faq.html#q19)，本轮不改变持久设置。

代码基于`88173f85`，测量时使用尚未提交的候选，精确执行源码摘要见[原始汇总](raw/summary.json)。
该组件阶段没有接入查询回调，只回答组件是否值得继续；后续接入及查询证据见下方服务器复测。

### 显式查询接入与条件

新增`remote_budget_mode=batched`，由实验回调在下一次事件循环推进时，合并已经就绪的最多16条记录；
单条就绪也会立即推进，不等未来请求凑满。每个事件循环使用独立队列，提交与请求内容观察均完成后才返回。
回调取消等待已排队事务完成，传输在返回后再次检查行取消；事务或观察失败不给该批请求发送许可，已提交记录不退款。
单独的`remote_request_batch`记录每次事务，逐行等待与事务累计分别解释。原同步/线程选择继续可用，默认仍为同步。

目标机器没有上一轮使用的PG软件目录。复制现存PG18.3软件到独立前缀，在数据盘以当前源码正常模式及
`PG_CFLAGS=-Werror`构建扩展，并只安装到新前缀；两臂使用同一扩展，旧安装的摘要保持。
完整查询执行源码按708份文件逐项核对，基于88173f85且测量时尚未提交的候选；源码清单、编译输出及扩展摘要保留在归档。
另保留一次上传尚未完成时读取源码清单的准备错误，发生在解包和查询前，请求0；上传完成后摘要核对通过。

PG18.3、Ray2.56.1、Daft0.7.21、Arrow24.0.0、psycopg3.3.4、httpx0.28.1；
Ray8逻辑CPU、256MiB对象存储、0GPU，两臂各一个worker与共享gateway，初始可用6CPU。
两臂均为C64、PG窗口256、Daft批次最多16行、2MiB传输窗口和4MiB对象额度，Daft8线程、统一退出遥测。
