### 统计本身会影响性能：现状与小范围设计

六路径都经过owner网关→固定全值router→模型API，保留同样的查询起止及完整响应口径。但相同接口不表示额外观察成本完全相同：N的performance模式省去预期请求重复构造，其他路径仍有各自的准备／调用事件；S又有payload子跨度。共同路径内还有同步两套预算记录、请求JSON／摘要、响应base64／JSON、protocol写入及SDK响应重放。网关trace先缓存在内存、查询后保存；不把全部日志误称每请求fsync。私有三跳账本的commit／状态更新在发送链内；每查询前后metrics GET与查询后官方评价另记，完整slot及运行总时间仍受其影响。
