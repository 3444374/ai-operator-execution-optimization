# 原生文本阶段与 KV 交接

本报告对应[当前计划](../../../plans/数据组织.md#native-stage-handoff)与
[后端说明](../../../../code/src/serving/backends/README.md#native-text-prefilldecode-handoff)。

## 实现与来源

新增两个独立模型进程的文本 prefill/decode owner，使用 vLLM 0.25.1 原生 NixlConnector。
逐条完整请求在 P 处理输入后，由 D 使用原请求和原生成参数产生完整结果；保留两段物理回执，
不把 P 的一次性 token 拼到新 prompt。每段独立 GPU 可见性，单主机可指定不同设备。
初版串行功能验证保持原身份；后续跨请求异步流水与同卡比较见下方2026-11-11小节。运行中 decode 状态迁移、视觉编码器分离与完整查询适配尚未实现。

工程参照为[固定版本代理](https://github.com/vllm-project/vllm/blob/v0.25.1/tests/v1/kv_connector/nixl_integration/toy_proxy_server.py)、
[原生 NIXL scheduler](https://github.com/vllm-project/vllm/blob/v0.25.1/vllm/distributed/kv_transfer/kv_connector/v1/nixl/pull_scheduler.py)
及[依赖](https://github.com/vllm-project/vllm/blob/v0.25.1/requirements/kv_connectors.txt)。
采用原生描述转发与失败策略，复用既有有限 IPC、进程所有权与清理；未修改上游模型计算或调度器。

## 可支持与尚未覆盖

本轮支持：在单卡、两个原生进程之间完成文本输入阶段与生成阶段交接，保持这四条请求的输出，并清理实际资源。
跨 GPU 的设备绑定代码已提供，但当前硬件没有第二张卡，不能据此声明跨卡实测通过。
上述原始功能验证未覆盖运行中 decode 迁移、视觉编码器分离、请求重叠、动态路由、完整查询适配和性能收益；后续流水实现与独立性能比较见下节。
NIXL与阶段分离是复用的原生能力，不作为本项目的新颖性结论。

### 实现、来源与边界

`PipelinedPrefillDecodeProcess` 使用两个已有 `AsyncEngineProcess` owner：每个 P 完成项立即进入 D，
不等待同批慢项；IPC 批提交与原生 continuous batching 分别保留。全程一个逻辑容量覆盖 P、待交接和 D，
D 完成才释放；返回恢复输入顺序，保留两阶段原回执。P 请求一个弃用 token，D 使用原完整消息和原生成参数，
不把 P 输出拼进新 prompt。动态路由、运行中 decode 迁移和完整查询适配仍未实现。

最终实机代码为 `ea1644a4daef32ef7e45974624f824cfe3c227d6`；Qwen2.5-1.5B-Instruct、vLLM0.25.1、
NIXL1.3.0。完整权重 SHA-256、模型 JSON／下载元数据、实际依赖及最终机器状态在
[汇总](pipeline-summary.json)和[原始证据包](pipeline-evidence-20261111.tar.gz)中。
[九份原生源码核对](pipeline-native-source-verification.json)与官方标签的完整 Git blob 身份一致，
该标签解析为上游提交 `752a3a504485790a2e8491cacbb35c137339ad34`，
包括 LLM.chat、AsyncLLM、scheduler、GPU worker／v2 runner 和 NIXL 统计；本轮未修改这些上游文件。
首次下载探针未取得源码，保留为 unavailable；随后通过 GitHub Contents API 的完整文件 blob 标识核对，
没有把下载失败解释为安装源码不一致。
Async 自定义统计接收无输出轮次的 NIXL 更新；P 端过期与 D 端传输按

### 原生批处理、状态交接与清理

独立 `observe01` 复用已有被动GPU观察，240个P原生请求和240个D原生请求通过返回的别名表完整关联。
实际输入准备／图决策的批大小峰值为P63、D120；未按ID后缀猜配，没有业务身份缺口。
41个有图决策的轮次中4个发生在业务请求前；其余1427个没有安排模型token，也没有图决策。
这些轮次仍可能处理KV传输，不能当作已执行模型计算或GPU空闲；原件全部保留。
采集正常关闭且没有已记录丢失；未采集kernel时长或证明P/D kernel同时执行。
该观察显著增加请求耗时（测量轮 1.055609 秒），
只作机制证据，不混入上述off时间，也不假定off具有逐轮相同批形状。

- q8：三会话含预热的原生接收 138960 次，原生报告字节 64879460352；P/D 原生运行请求峰值 63/118。两阶段完成计数均与逐会话逻辑请求数一致，失败／通知失败／过期为0。
- copy：三会话含预热的原生接收 8448 次，原生报告字节 5284823040；P/D 原生运行请求峰值 63/64。两阶段完成计数均与逐会话逻辑请求数一致，失败／通知失败／过期为0。
