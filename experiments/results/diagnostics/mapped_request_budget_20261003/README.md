# 同机共享预付计数：本地组件与Core替身对照

共享计数原型已通过本机检查。组件完成16,384次领取，Core替身完成8,224次模拟调用，HTTP／模型／PG均为0。
Core完整fixture中位数0.864303→0.700667秒，少18.933%；把计数准备、执行器准备与退出也计入后，
0.873357→0.717139秒，少17.887%。这是观察设施的本地信号，不是SQL、GPU、真实模型或原生系统加速。
正式查询默认与真实计费方式保持；原型还没有接入正式runner。

## 实现与适用条件

按[查询调优清单](../../../plans/查询调优.md#同机共享预付计数的本地原型)继续已有观察成本归因。
参考生产源码为main `53155f8c`，未改变Core、PG、Ray Map传输或模型服务；新增内容位于实验组件和本地诊断API。
本机为Darwin arm64、Python3.12.6、SQLite3.45.3，未安装厂商库、连接服务器或调用外部服务。

[组件源码](../../../../code/src/experiments/mapped_request_budget.py)复用现有`reserve_unit/claim_unit`，
发送前把整个有限单元持久预付并独占领取；允许的摘要与次数在准备时确定。
共享状态保存已领取编号和各摘要剩余次数，每行通过文件锁登记；另一个文件锁表示所有者仍存活。
没有worker专属额外额度，不选择或重排行，不增加模型活动名额，不改prompt、输出或模型内部批处理。
依据为Python的[mmap](https://docs.python.org/3.12/library/mmap.html)、
[fcntl](https://docs.python.org/3.12/library/fcntl.html)与[fork通知](https://docs.python.org/3.12/library/os.html#os.register_at_fork)接口，这是工程决策。

- 活动client及owner不能复制到其他进程；只传descriptor，接收进程打开独立句柄，核对文件、实例及准备清单。
- 同一单元的编号只有一个递增前缀，重复摘要按准备次数独立计费；错误摘要、过期、关闭或所有者退出后不再领取。
- 登记先标记未完成；调用方在更新期间崩溃则整单元拒绝继续，不修复计数、不退款。领取后尚未发送的编号仍消费。
- 可变共享状态不作为逐行持久日志；安全总额来自已持久预付的整个单元。所有者丢失后不会重建或恢复领取。
- Python fork会关闭继承的现场句柄；第三方C fork、Linux时间命名空间、不同文件系统和跨机仍须另查。

当前只支持同机、本地目录、单次启动的已知有限请求，每单元至多4096条，状态文件至多196,672字节。
本组件确认的是领取行为；关闭预算不能证明已经发出的模型请求结束，也不释放未知模型工作或数据库资源。
真实端点、SQL生命周期、多机、训练、动态生成请求集合与模型质量均为pending。

## 清单与全部重复

组件为原逐条SQLite与候选各1／4个Python进程，每项1024条，一次预热、三次交错测量，共16次执行、16,384次领取。
输入摘要来自固定fixture，127种摘要有重复；核对全部行标识、摘要、唯一编号、持久总额和调用方退出。
共享映射实际6,160字节；没有GPU、HTTP、厂商SDK或数据库服务。每次30秒、整体5分钟，首次错误即停并保留。

## 行为检查、失败与复算

17项组件检查覆盖多线程／多进程唯一编号、重复次数、关闭、过期、错误身份、继承句柄、所有者与调用方崩溃、禁止重建及预付总额。
9项Core诊断检查覆盖新模式与旧模式、关联／资源、失败以及未知结果；另78项账本、观察器、计时与Core检查通过，共104项。
正常发送阶段没有SQLite事务或fsync；仍有文件锁和内存写入，这些成本进入组件／fixture计时。

复核时发现错误注入在标记“不确定”后仍返回成功，却期待传输按正常路径释放；传输正确保留了未知记录。
原失败日志和当时测试源码保留，修订为两项独立检查：预算未确认即报错时归还未发送引用；错误guard返回成功时保留未知传输记录。
同时补齐预算关闭报错时client句柄仍会归还的诊断清理路径，以及文件不可用时的预算错误类型。
计时代码的精确快照在归档，后续改动仅涉及这两项异常处理；没有重写正常重复或隐藏失败。

数字来自[聚合](raw/analysis.json)，[复算脚本](raw/recompute.py)核对[清单](raw/storage-manifest.json)及
[1,705,410字节归档](raw/evidence.tar.gz)的99个成员，再逐条核对16,384次组件领取及10次Core原始分析。
SQLite、共享状态／所有者文件和重复投影流只保留仓库外原件，备份标识`GPU-mapped-request-20261003`；未删除原件。

```sh
PYTHONPATH=code python3 experiments/results/diagnostics/mapped_request_budget_20261003/raw/recompute.py --output /tmp/new-mapped-analysis.json
```

输出须尚不存在，该命令只读已有证据，不启动进程或服务；计算口径和全部重复可精确复核。

## 服务器何时需要

本轮本地工作已完成，不要求现在开机。下一段可先在本地完成观察器与监督器接入准备，随后需要服务器做Linux、真实Ray／Daft与PG生命周期检查。
当前`NativeSessionFactory`不能直接传递活动client；须在实际进程内用descriptor打开和归还。
现有监督器的`close_shared_unit`不会通知这个独立共享状态，不能只换一个claim函数；必须由所有者关闭状态并管理全部调用方。
各路径的完整请求身份、序列化差异、取消／错误、重复／重试和未知记录须沿真实SDK核对，才能考虑正式实验选项。
先用确定性HTTP替身、模型请求0验证，再准备独立的真实模型有限计划；旧请求额度不复用。
本轮只支持继续准备这一观察候选，不采用新默认，不宣称已完成统一正式观察或SemLoom算法调优。
