有限localhost fixture，GPU／模型0，1800 POST，13.949/90秒；[具体计划](../../../../plans/查询调优.md#replica-adaptation)。
复用已有两槽HTTP fixture与同一完整请求Core重放；每次96请求，work均1，payload与响应关联／计费／清理检查通过。
A的非抢占服务时长6ms，在first-offer+0.12秒后变40ms、+0.40秒恢复6ms，B一直18ms；没有额外背景调用，真实GPU不受干扰。
RR独立24请求校准K2/4/8选K8；固定rate与在线rate均使用相同合法估计work、同一completion accumulator transport边界。
K2只揭示路由机会，不是最优静态点；同K三臂配对，K8保留更强静态资源点，不能跨K归因算法。

K2首轮在线A反馈约0.116秒159.13 req/s、0.434秒48.52、0.799秒195.89；变化后反馈有窗口／EWMA滞后，恢复也滞后，含client/queue时间，不是实际GPU吞吐。
K8第一轮仅在0.274/0.294秒收到第一批rate，完成前没有新的恢复rate；服务记录覆盖恢复阶段不等于控制器已学到恢复后的稳定capacity。
三个K8在线cell均覆盖A恢复（12／14／14请求），不能因此称持久在线适应已成立。
