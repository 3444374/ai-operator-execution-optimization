# experiments/results/AGENTS.md

继承上级规则。结果入口见 [README.md](README.md)，报告内容与证据要求按
[实验规则](../AGENTS.md)执行。本文件负责结果、日志与归档的保存和精简；动机与可行性结果也引用这些保存要求，保留各自实验身份。

## 保存什么

- 以实验标识关联研究问题和计划，以运行标识区分每次实际执行；重跑使用新标识。运行元数据记录
  开始、就绪、结束时间、退出状态与失败原因；未采集项写明原因，未运行的内容留在计划中。
- 按独立核验与复现价值选取材料，不设固定文件数或字节数。保存实际配置与来源、适用的环境与版本、
  全部重复值、核验结论所需的原始观测、关键日志及实验结论。结论保留实际对照、适用条件与尚不能支持的判断，
  链接对应数据和计算来源；报告长度与实际问题相称，已有技术说明用链接引用。
- 失败、中断、排除、慢样本和负结果保留运行身份、原因及必要原始证据，与有效聚合分开。
  精简样本注明完整来源、筛选规则与完整样本数；全量尾延迟、资源峰值或质量结论须有对应的完整观测。
- 同一原始数据、配置或日志保存一个可定位的副本，各运行以路径或归档成员、SHA-256 校验值及运行标识
  明确映射。内容相同不代表运行相同；保持原始观测及各次执行的来源关系。
- 同一派生分析保留一份当前输出及计算入口；可从保留证据精确重算的大量展开文件按需生成。
  更正分析注明原因与版本，保留原始观测及被引用的旧分析；报告和实验小节引用同一份数字来源。

- 每个实验维护一份主报告，通常为`README.md`；阶段诊断、补充分析和结论更正进入同一报告的相应章节，
  直接引用数据与计算入口。可重生成的Markdown表并入报告，机器可读聚合继续保留；独立问题或不同运行身份不强行合为一次实验。
- 结果导航只定位报告与证据，台账记录证据身份和可支持的判断；不在多个入口逐项复制同一运行摘要、参数与排名。

## 放在哪里与如何精简

- Git 保存脱敏报告、必要的紧凑原始观测、复算入口和来源记录。临时构建、会话过程、重复导出及
  无独立核验价值的完整调试输出放 `tmp/` 等忽略目录或仓库外 artifact 目录。长期图表仍放 `figures/`。
- 大量原始文件可无损压缩或去重；复用已有清单记录原路径、保存位置、字节数与 SHA-256，
  去重项给出恢复来源或可精确重算的方式。脱敏原件与公开副本分别记录校验值。
  Git 中的 Markdown 链接必须指向公开可见文件；仓库外原件用运行标识、校验值和获取方式说明来源。
- 精简前核对反向引用、唯一内容、是否仍有写入进程及恢复位置。改动后核验全部受影响成员的
  字节数、校验值和恢复映射，更新现行报告、索引与必要证据台账；历史日志保留原叙事及替代说明。
  独立备份完成并核验前保留原件，同盘副本只作恢复暂存；不能因结果不好或已被新结果替代而删除证据。
- 完成检查包括本次文字用词、Markdown 本地链接和 `git diff --check`；进入 Git 前按根隐私规则扫描。
  单机路径、完整清单和处理过程放本地或仓库外；规则文件只保存长期行为要求。

## 实验命名与来源定位

- 新结果目录以对象、研究问题或验证用途及首次观测日期命名，使用小写snake_case；同日独立执行由运行标识区分。
- 报告标题说明实际对象与对照。设备、模型、样本、资源、重复、状态和配置修订在元数据中记录；日期不随补充报告改变。
- 目录整理可改善读者入口；原始实验与运行标识、系统臂、来源、配置版本和原始观测保持可追溯，旧路径映射记入项目导航。
