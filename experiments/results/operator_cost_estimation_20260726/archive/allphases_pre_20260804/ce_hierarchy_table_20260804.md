## Headline

Heinrich SIGMOD 2025 "accuracy != selection" confirmed across the full hierarchy:
- CE5 hybrid: BEST MAE (8.73) + BEST pick_rate (0.55), but regret 16.58% (high).
- CE3 ridge: BEST pairwise (0.774) + topK5 (0.60), but WORST regret (22.76%).
- CE2 lookup: WEAKEST-learned MAE (16.00), but BEST decision regret (5.63%) + best Spearman (0.691).
- CE1 analytical: BEST Q95 tail error (3.42) + best interval coverage (0.91).
- CE4 lightgbm: on this small data (283 rows / 3.6 contexts) it UNDERPERFORMS simpler
  models (Spearman 0.417, worst Q95 6.82) and is overconfident (coverage 0.60 at the
  narrowest width 17.11) — consistent with "simple models suffice on small data".

=> A lower-MAE / higher-pairwise estimator does NOT make safer plan-selection decisions.
   No estimator currently meets the promotion thresholds (median regret <=5% AND
   pairwise >=0.75): CE3 meets pairwise but not regret; CE2 meets regret but not pairwise.
   None can take over scheduling yet — feasibility-stage result.

## Caveats

- Selection metrics (pick_rate / decision_regret) are NOISY: only ~3.6 multi-candidate
  decision contexts per seed (the 283-row profile yields few per-split). Prediction +
  global-ranking metrics (MAE, Spearman, pairwise, topK) are over the full test set
  (39-87 rows) and more reliable.
- Static pre-execution track only. The project method's runtime-state correction
  (Track 2: Ray pending/running, vLLM running/waiting, active-work) is not yet
  exercised — the 283 rows do not carry per-config runtime-state labels.
- text (AI_COMPLETE) only. Image (AI_EMBED/CLIP) cost estimation needs a separate
  profile (the 60K 2-arm has too few cells) — deferred.
- lightgbm native API (lgb.train+Dataset) used to avoid the scikit-learn dependency.
