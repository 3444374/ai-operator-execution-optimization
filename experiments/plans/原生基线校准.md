本计划区分两个问题：已有 LOTUS 方法＋框架执行图中的工程限制是否合理，以及直接使用框架原生 AI API 的
SemBench 端到端表现。不是官方 runner 复现声明，也不将依赖版本不同的产品比较解释成纯调度收益。
接口与默认值归[执行配置](../../docs/执行配置与优化开关.md#native-baseline-controls)，实现资格归
[代码状态](../../code/INFRA_STATUS.md)，正式指标沿[对照规范](reference/对照规范.md)。
首测失败与后续CPU修复见[诊断报告](../results/diagnostics/native_sembench_q3_20261106/README.md)，

## 全部原生 baseline 的正确性与公平资格

本节是后续准备与验收的当前要求；下文具名 Movie Q3、HTTP、版本和批次记录保留原实验范围，不自动成为新运行命令。
先逐项完成原生路径正常运行、正确性和公平资格，再评估哪些结果需要重测。本阶段不启动全量重跑；
SemLoom 新测试后置，不为准备 baseline 改动其生产调度。按用户最新澄清，各 baseline 保留各自原生依赖和实现，
尤其 Kalypso；共同硬件与实际计时边界优先统一，不为追求相同软件版本阻塞正确性资格。

### 原生身份与共同条件

原生 LOTUS accessor/LM、Daft AI prompt/provider、Ray Data LLM 官方 processor、作者 DuckDB＋IMLane、
Kalypso 作者 SemanticPlan/KV 执行分别拥有自己的计划、批次、调度和生命周期。相同 LOTUS 任务语义可以共用；
LOTUS＋Ray/Daft/IMLane 旧适配器、项目 resident 生命周期、作者补丁版与原生默认路径分开命名。
不能把一个 CLI 的 backend 标签当原生身份，也不能把未支持项替换成普通 Python UDF 填满表格。

每个“数据场景 × 题目 × 原生系统 × 生命周期 × 版本配置”是一项资格。对照前按下表冻结实际值，
缺失项写 unavailable 与原因，不用默认值、旧报告或相同模型名补齐。

| 条件 | 所有可匹配系统共同固定 | 保留并记录的原生差异 |
|---|---|---|
| 源与任务 | 数据文件字节摘要、规模、完整源序、发生项身份、选择/NULL/去重规则、SemBench 提交与任务定义、完整关系 sink | 框架原生扫描、物化与执行计划；部分输入、独立查询、联合 DAG 不能混排 |
| 模型资产 | 权重 revision/分片摘要、tokenizer/config/chat-template、图像 processor/resize/frame 规则、dtype、量化、上下文容量 | 作者接口不支持的模型能力须明确，不降级模型冒充同配置 |
| 语义 | 经公开输入接口可传入的完整消息、角色/字段顺序、模板后的 token 数组、parser、错误/NULL/default 策略、原关系操作与评价器 | 作者内置模板、解析、采样/校准/重试属于算法时保留作者组；不能修改后仍称原版 |
| 生成 | 每题显式 max_tokens、temperature、top_p/top_k/min_p、seed、n、stop/stop_token_ids、惩罚、JSON/schema/引导解码、截断和重试政策 | 不支持项标明；requested 与引擎 resolved 值都保存，不能只核配置文件 |
| 引擎与依赖 | 同一硬件；逐系统冻结实际 vLLM、Torch、CUDA、transformers、驱动、Python、编译/attention backend 和 wheel/source/二进制身份 | 各自原生依赖、作者扩展和官方版本约束保留；不同版本不阻塞资格，差异必须披露 |
| 缓存与历史 | 模型结果缓存关闭；冷轮无额外任务预热；同组使用一致 prefix/KV/MM-cache 政策、查询顺序和历史 | 编译、OS page cache 与引擎原生初始化单列；未清系统缓存不叫完全机器冷态 |
| 资源 | 同机器/GPU 型号数量、CPU affinity/cgroup、RAM/SHM/磁盘上限、功耗/时钟条件及同一隔离规则 | native executor、线程、batch、queue、prefix routing 等保留合理原生配置；不以统一小并发削弱对照 |
| 容量与调优 | 相同硬件/外部资源边界；各系统有同等有限校准机会，原生容量和有效值在测量前冻结并回读 | 不强制各版本的容量参数机械相同；引擎 seq/token 上限、SDK batch、API 在途和 GPU 实际运行序列分别记录 |
| 观测 | 相同事件定义、观测开关和采样频率，逻辑行、API 尝试、引擎终态、generate/add/kernel 各自实测 | 未拦截层级留空；MFU、预算和终态条数不能伪装为独立 generate/kernel 计数 |
| 输出与质量 | 原结果及逐发生项原答、解析结果、finish reason、token/重试、原 evaluator 和必要独立质量审计 | 保留不规范/冲突输出与原指标，不后改 parser 或默认值提高分数 |
| 重复与失败 | 相同独立重复单位、执行顺序安排、超时与停止规则，全部原值/失败/重试保留 | 同 owner 连续 warm 不当独立 cold 重复，联合任务的子题不能拆成独立重复 |

共同参数按任务冻结，不对所有题机械使用同一 max_tokens。原 SemBench 文本参考的 8192、无 stop
与历史显式短 Filter 配置必须区分；MMQA Q4 的 JSON-object 约束不能自动套到其他任务。
固定输入正确性检查离线进行，不在性能测量前预执行模型。预检若读取全数据或模型文件，记录由此形成的缓存历史。

### 统一的实际计时事件

所有时刻来自同一机器的单调时钟，并记录进程、时钟域与事件来源。阶段可能重叠，不能盲目相加或事后扣减猜测时间。

1. cold_total：独立 controller/runner 开始，到原任务完整关系结果对调用方可见。包含该运行发生的进程导入、
   runtime/图/actor/模型初始化、源读取和准备、执行、结果恢复与 sink。下载、安装及离线资格不计入，但另报。
2. query_full：本次 fresh 查询进入、源读取/准备开始，到同一完整 sink。首次懒初始化实际发生在区间内就计入。
   不把只从 execute、首条请求或模型 ready 开始的时钟叫全查询。
3. model_ready：实际模型可接受请求的观测及 owner/model PID、出生时间、engine UID；runtime ready 不代替模型 ready。
   冷轮 ready→sink 仅为冷轮尾段，不能冒充独立 warm 查询或纯模型时间。
4. first_request / last_terminal：分别记录首个原生请求提交、引擎首个接受及最后一个确定终态；区分 API 和引擎层级，
   缺观测留空。首提交→末终态包括实际排队/传输/服务，不是纯 GPU kernel 时间，也不替代完整查询；
   model ready→首提交与末终态→原 sink 分别报告，不能由不完整或未配对请求推算。
5. warm_full：同一 owner 和模型实例，上一轮完整结果结束后重新执行完整源/任务/sink，区间与 query_full 一致。
   核实结果缓存关闭、真实调用和 prefix/KV 政策。原生 API 不能保留模型时记不支持/待实现，不把 runtime 复用称 warm。
6. sink timestamp 紧接完整结果可见处，质量评价、snapshot、断言审计、证据持久化与最终 owner close 统一后置并各自记录；
   若原生必要 drain/finish/close 在完整结果前不可移出，它属于被测路径并计入，不为计时改算法。
7. API 正常返回、结果持久化、owner 关闭、进程/GPU/SHM/socket 回收各有事件。结果已出但公共 API 失败、
   资源残留或未知请求，不计为完整通过。计时终点不能用清理成功替代，也不能把失败清理抹去。

历史 Q4 的 SemLoom 60.737 秒与 LOTUS 45.608 秒都包含首轮准备与初始化，且前者不含此前 Ray runtime 启动。
两条旧 sink timestamp 的 snapshot/审计位置也不完全相同；它们保留原身份，不追认成完全匹配的纯查询对照。
旧值可由原始事件重算解释，但改版本、缓存或生命周期后不得沿用为新配置成绩。

### 分层资格与连续执行入口

- G0 原生身份与支持：固定源码/作者提交、实际入口及最窄适配 diff，逐题核实原版能力。
  表格严格区分 unsupported、blocked、unprepared、CPU-qualified、model-qualified、fair-comparison-qualified。
  原版不支持的成绩留空；缺接线或缺依赖不能写成作者不支持。
- G1 软件 CPU：完整源身份、所有消息/token、effective 参数、按源发生项绑定的答案回放、完整原 sink/evaluator；
  缺失/重复/乱序、预算越界、失败/取消、一次关闭与资源归属须有必要故障用例。CPU 回放不是模型成绩。
- G2 环境与真实模型：在固定隔离环境核 imports/API/依赖，按确切有限范围完成原生引擎启动、
  真实请求与输出/解析/质量、失败结清和物理清理。版本改变只重做受影响资格，不重复已有同签名证明。
- G3 公平性：比较两条实际 manifest 与事件；任何影响输入、输出、缓存、资源和时钟的差异均须消除或明示分组。
  同硬件、各自原生版本的完整系统比较是有效目标；软件/算法差异不能归因成纯调度收益，也不单独构成资格失败。
  语义准确性不要求所有模型原答逐字相同，但未解释的技术错配、未知请求或错误统计不能进入排名。
- G4 正式比较：全部计划内可支持 baseline 的 G0–G3 状态明确后再决定是否重测。
  若需要，预先冻结每组独立重复数、顺序及 cold/warm 单位；资格单次、行数或联合批次不能代替性能重复。

服务器由既有协调者持唯一 host/GPU 租约，按已冻结队列执行；本计划不新增常驻调度器、控制器副本或 GPU owner。
复用现有监督、预算、资源采样及原生入口；共同代码只处理输入合同、观测、sink/评价和资格，不接管原生调度。
任何输入/参数漂移、缺失/重复、unknown、未核 retry/restart、资源越界或未确认退出，停止该项并保留证据；
其余独立 CPU 工作可以继续，不自动重试整轮。

本次公开 `files/movie/data/sf_2000/Reviews.csv` 原字节 SHA256 为
`df231cfb189c9e169aa6afe415e4fa24533b04499179bbd61416c4c6af28ca21`，Git blob 为

旧4016次 campaign 不是此输入，不能混合或按重复实验删除。

[中立任务合同](../../code/src/baselines/text/sembench_movie_native.py)不导入 LOTUS 或 SemLoom 执行器。

对这些消息调用 `apply_chat_template(tokenize=False, add_generation_prompt=True)`。运行前须比对实际模板输入，

质量同时报告原 MovieEvaluator._evaluate_q3 及120条的 TP／FP／TN／FN、未解析数和 count error。
COUNT 恰好相同不能掩盖 FP／FN 抵消。审计和计数消费同一份物化预测，不为审计重新执行 AI 图。

## 三条直接原生接线

| 路径 | 实际 API／执行归属 | 依赖与当前状态 |

## 有限校准与后续比较

先以各系统的原生／作者配置建立有效点，再按实际瓶颈每次只改一个应用参数；以下是候选，不是已运行或最优配置。

| 既有路径 | 保留的依据点 | 最多先尝试的变化／边界 |
|---|---|---|
| LOTUS 客户端 | SemBench 作者20 | 与 SDK64 比较；两者都不是模型容量，保留同一生成和完整120行 |
| Ray 普通同步 records | 一个完整 EOF／关闭 owner | model_batch_rows4→32→128；不盲增actor或仅堆排队任务。新 Ray LLM 路径另列 |
| Daft 普通 records | native线程默认＋现有批4 | 批4→32→128；原单线程 session 仅作独立限制诊断，不作普通默认。补充 fused 图 cpu_workers1 保留真实能力 |
| IMLane records | 一个已验证的 CPython／模型 owner、显式 pending | 批4→17→64，先通过确切 wire byte预检；pending2→4单独比较。作者默认4 executor若会新建4个私有模型则不直接采用 |
| Kalypso | 作者服务与生成默认 | 先保持作者执行／容量，不移植其他引擎值；独立全局查询状态仍串行 |

新直接原生路径先用原生默认；只有120行不足以维持供给且观察到瓶颈时，才评估一个不同 batch／buffer 点。
每个候选最多一次预演，不自动搜索。预演配置未变且证据完整时可作为第一轮，避免重复完全相同的已测工作。
正式对照采用三轮交错顺序，保留全部单值、质量与成本；三条路径都具备资格时为9次查询、1080个逻辑请求，
准备阶段的额外真实请求另行累计。Ray LLM 无公开跨查询模型常驻保证，首批不发布 resident 比较；
已有普通 session 的常驻结果、模型启动和 runtime-only复用分别报告。
