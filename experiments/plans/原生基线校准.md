# 原生基线校准

本计划区分两个问题：已有 LOTUS 方法＋框架执行图中的工程限制是否合理，以及直接使用框架原生 AI API 的
SemBench 端到端表现。不是官方 runner 复现声明，也不将依赖版本不同的产品比较解释成纯调度收益。
接口与默认值归[执行配置](../../docs/执行配置与优化开关.md#native-baseline-controls)，实现资格归
[代码状态](../../code/INFRA_STATUS.md)，正式指标沿[对照规范](reference/对照规范.md)。本批只准备源码和 CPU 验证，未启动 GPU。

## Movie Q3 的固定语义与输入

使用 SemBench `c814e3807e72d4cf876b852b17e77f3cc94575c2` 的
[原 Q3](https://github.com/SemBench/SemBench/blob/c814e3807e72d4cf876b852b17e77f3cc94575c2/src/scenario/movie/runner/lotus_runner/lotus_runner.py)：
完整读取 Reviews，先按 `id == "taken_3"` 筛选，再判断
`Determine if the following review is clearly positive. Review: {reviewText}`，最后 COUNT 返回 `positive_review_cnt`。

本次公开 `files/movie/data/sf_2000/Reviews.csv` 原字节 SHA256 为
`df231cfb189c9e169aa6afe415e4fa24533b04499179bbd61416c4c6af28ca21`，Git blob 为
`710028a863dbf04853e45a3e618113dff7521b4d`；本地已核实654791字节、2000行、1865个唯一 reviewId。
普通筛选后120行，120个唯一 reviewId，无空 reviewText；标签14 POSITIVE／106 NEGATIVE。
仍按完整源位置生成 occurrence_id，不假设业务 reviewId 唯一，不去重、不截断，不向模型提供标签。
旧4016次 campaign 不是此输入，不能混合或按重复实验删除。

[中立任务合同](../../code/src/baselines/text/sembench_movie_native.py)不导入 LOTUS 或 SemLoom 执行器。
消息与普通 Qwen 模型的 LOTUS1.2.4 DEFAULT、非 CoT Filter 做真实 SDK CPU 差分：
原上下文格式、原指令、原 Answer 解释、True 优先和解析失败 default=True 均保留；另显式记录 unparsed 数。
Ray 使用原生 chat-template stage；Daft 的原生 AI 表达式接收原始字符串，由同一个模型 tokenizer
对这些消息调用 `apply_chat_template(tokenize=False, add_generation_prompt=True)`。运行前须比对实际模板输入，
不能把 raw 文本直接交给 Daft 而声称模型输入相同。此合同不扩展到 DeepSeek 专属后处理或其他序列化格式。

质量同时报告原 MovieEvaluator._evaluate_q3 及120条的 TP／FP／TN／FN、未解析数和 count error。
COUNT 恰好相同不能掩盖 FP／FN 抵消。审计和计数消费同一份物化预测，不为审计重新执行 AI 图。

## 三条直接原生接线

| 路径 | 实际 API／执行归属 | 依赖与当前状态 |
|---|---|---|
| Daft 原生 AI | 完整 cohort→native Filter→`daft.functions.ai.prompt(provider="vllm-prefix-caching")`→原生异步模型→一次 collect→Filter／count_rows | [绑定](../../code/src/baselines/text/frameworks/daft_sembench_native.py)已准备；Daft0.7.21 的表达式／普通关系有 CPU 资格，真实模型未验。provider 上游标为 experimental；不采用已弃用的 llm_generate |
| Ray Data LLM | 完整 cohort→Dataset.filter→`vLLMEngineProcessorConfig`／`build_processor`→原生异步模型→一次 materialize→原生 Filter／count | [绑定](../../code/src/baselines/text/frameworks/ray_data_sembench_native.py)已准备；公开 API 合同使用 CPU 替身。实际 Ray2.56.1／模型环境未启动；其 LLM requirements 固定 vLLM0.22.0，不能沿用未经资格检查的0.25.1 |
| DuckDB＋作者 IMLane＋语义 UDF | 修改版 DuckDB 的实际 prediction operator、DBEnd／coordinator、作者 CPython executor；UDF 仅提供相同语义内核 | 待作者构建、同名函数注册和 Arrow 结果转换验证。当前 records bridge 不是该数据库路径，普通 pip DuckDB Arrow UDF 也不替代作者集成；未验证项留空 |

Ray 原生 processor 默认 batch32、concurrency1、max_concurrent_batches8；这些是该版本原生值，
不是旧同步 adapter 的固定8请求。actor 原生重试／重启可为 -1；120只是逻辑请求数，不能冒充物理尝试上限。
本绑定不改重试策略，外层须记录实际 retry／restart、设置期限；发生重试／丢失或无法核实尝试数时，
保留诊断结果并停止性能结论，不自动重跑。
CPU 阶段支持的 concurrency 可以调；此 pin 的 stage batch_size 实际会被 processor batch_size 覆盖，不能发布无效旋钮。
真实 builder 会初始化 Ray、读取／下载模型元数据，不能在所谓零模型 CPU check 中直接调用。
来源：[原生 processor](https://github.com/ray-project/ray/blob/ray-2.56.1/python/ray/llm/_internal/batch/processor/vllm_engine_proc.py)、
[requirements](https://github.com/ray-project/ray/blob/ray-2.56.1/python/requirements/llm/llm-requirements.txt)。

Daft 保留 native runner 默认线程数；不注入1线程。本地 native sink 的 max_concurrency1 是管线任务数，
LocalVLLMExecutor 仍异步提交多条模型请求，不等于模型只能处理一条。max_buffer_size5000／min_bucket_size16、
prefix_match_threshold0.33／do_prefix_routing=True 沿上游默认或明确覆盖；此处 prefix routing 是本地排序／分桶，
并非跨 actor 路由。batch_size 设置严格 morsel，不等于 vLLM 请求并发或计算批大小。
concurrency／gpus_per_actor／load_balance_threshold 仅分布式路径生效，当前 native 绑定拒绝这些覆盖；
`num_gpus` 也未传到表达式，不能当有效配置。小于5000的120行可到EOF统一排空，这是原生实现，不据此擅改算法。
来源：[native sink](https://github.com/Eventual-Inc/Daft/blob/v0.7.21/src/daft-local-execution/src/streaming_sink/vllm.rs#L360)、
[异步 executor](https://github.com/Eventual-Inc/Daft/blob/v0.7.21/daft/execution/vllm.py#L111)。
Daft0.7.21 的 Ray extra 要求 Ray<2.56，因此本次用其 native runner，并与 Ray2.56.1 LLM 环境隔离。
原生表达式不公开每条 token usage、resolved capacity 或可靠模型关闭回执，缺项留 unavailable；
外层按实际日志／服务观察补足，不能用请求配置代替回读。

作者 IMLane 固定来源为
[`072f8257db80569e42c9f5727d839587df529652`](https://github.com/IM-DM4AI/IMLane0/tree/072f8257db80569e42c9f5727d839587df529652/database/duckdb)。
`PREDICTION` 走本地 BatchingExec，不能标为完整 IMLane；`SCHEDULE_PREDICTION` 的 ProcessSchedExec
在该 pin 是直接 FINISHED 的空实现。实际 PROCESS／THREAD_SCHEDULE 分支还须核实函数注册和结果转换，
不为凑结果换回普通 Python UDF。
作者 Arrow bool 为 bit-packed，固定转换器的 raw-byte 分支须验证；可评估非空 int0／1＋SQL `=1`，
保持同一布尔语义，并先做 CPU 批次／类型／寿命检查。完成前不安排模型。
论文 Q7 使用 SemBench Movie Q3，但为1M行表、远程 Qwen3-1.7B／vLLM；本次2000行／共同7B模型是项目对照，
不声称复现论文绝对时间或其配置最优。论文依据见[精读记录](../../docs/research/精读文献笔记/imlane_pvldb2026/imlane_pvldb2026.md)。

## 模型、规模、时间与停止条件

先使用既有已验证的 Qwen2.5-7B-Instruct 模型资产；执行前记录精确 revision／权重与 tokenizer 身份、
BF16实际生效值、GPU／驱动、CPU与cgroup资源、框架及模型环境版本。缺少当前平台检查或依赖不兼容时仅报阻碍，
不修改运行中的环境。每次至多一个占用同一张 GPU 的模型 owner；作者 CPU executor 数不等同于新增 GPU 模型数。

共同生成条件为 temperature0、top_p1、max_tokens8192、无 stop、默认零惩罚／repetition1、单输出；
seed及实际引擎参数记录原值。上下文／seq／batched-token 等容量省略项由各自原生版本解析并回读，
不隐式设8／4096，也不强行统一成大并发。不同 vLLM 版本的结果是原生产品路径对照；
需要隔离框架收益时另验证兼容的共同模型引擎，不能仅凭相同模型名作因果归因。

首批只安排 Daft、Ray 各一次完整冷查询：各120个逻辑请求，共240；IMLane 上述准备通过后再增加120，共360。
不预热、不执行其他题目、不自动重试完整查询。每个逻辑请求正常生成一次时，输出上界分别为每路径983040 token、
三路径2949120 token；这不是预计用量，也不覆盖内部重试。重试／诊断实际消耗另外累计，当前没有物理总 token 上限保证。
框架原生的内部启动／warmup计入启动时间，不伪装成免费的模型常驻。

尚无这两条新路径的实机耗时，不能从旧 adapter 时间推算。给首个组合的工程期限为启动600秒、完整查询600秒、关闭120秒，
单组合最多22分钟；先有一次真实预演再给后续时长估计。构建／安装时间单独计，不从查询预算扣除。
每条记录从源扫描、预处理／模板、native runtime／模型启动、推理到原生计数与关闭的完整时间，评价另计。
Daft 缺少公开关闭回执时，以独立监督进程退出和 GPU 持有者观察判断；未知不填成功。
Ray 只关闭自己创建的 runtime，调用方已有 runtime 单列身份；首批使用独立新进程取得冷路径。

停止条件：输入／模板／输出关联改变、缺失／重复 occurrence、真实生成配置不符、质量差异尚未解释、
重试／重启、资源超限、期限到或模型进程未确认退出。失败原件与诊断成本永久保留，不补成功时间、不把不支持项填0。

## 有限校准与后续比较

先以各系统的原生／作者配置建立有效点，再按实际瓶颈每次只改一个应用参数；以下是候选，不是已运行或最优配置。

| 既有路径 | 保留的依据点 | 最多先尝试的变化／边界 |
|---|---|---|
| LOTUS 客户端 | SemBench 作者20 | 与 SDK64 比较；两者都不是模型容量，保留同一生成和完整120行 |
| Ray 普通同步 records | 一个完整 EOF／关闭 owner | model_batch_rows4→32→128；不盲增actor或仅堆排队任务。新 Ray LLM 路径另列 |
| Daft 普通 records | native线程默认＋现有批4 | 批4→32→128；原单线程 session 仅作独立限制诊断，不作普通默认。补充 fused 图 cpu_workers1 保留真实能力 |
| IMLane records | 一个已验证的 CPython／模型 owner、显式 pending | 批4→17→64，先通过确切 wire byte预检；pending2→4单独比较。作者默认4 executor若会新建4个私有模型则不直接采用 |
| Kalypso | 作者服务与生成默认 | 先保持作者执行／容量，不移植其他引擎值；独立全局查询状态仍串行 |

新直接原生路径先用原生默认；只有120行不足以维持供给且观察到瓶颈时，才评估一个不同 batch／buffer 点。
每个候选最多一次预演，不自动搜索。预演配置未变且证据完整时可作为第一轮，避免重复完全相同的已测工作。
正式对照采用三轮交错顺序，保留全部单值、质量与成本；三条路径都具备资格时为9次查询、1080个逻辑请求，
准备阶段的额外真实请求另行累计。Ray LLM 无公开跨查询模型常驻保证，首批不发布 resident 比较；
已有普通 session 的常驻结果、模型启动和 runtime-only复用分别报告。

## 清理与恢复

只删除无调用的错误辅助、重复可生成中间产物和已经验证替代的旧限制。旧短生成配置、4016次不同输入、
ZMQ零观测调用失败、修复前后的解析／空结果证据，以及需要重建的作者桥来源都保留准确身份。
现有兼容入口仍有真实消费者时不删。运行中的目录、唯一数据、原实验记录与研究方案不按“旧”批量清空。
临时数据／完整调试输出在仓外；Git只保存必要源码、合同与可解释的失败／修复说明。
