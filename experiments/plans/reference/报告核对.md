# 报告核对

本清单落实[实验规则](../../AGENTS.md)、[结果保存](../../results/AGENTS.md)与[对照规范](对照规范.md)，
只核查适用于本次任务的项目，不另设统一运行门槛。早期 vLLM／nginx 双后端实例、固定重复数及旧 gate
按[原清单快照](https://github.com/3444374/ai-operator-execution-optimization/blob/277d8f4862c291bc2830cc6622f5a0b4f28b5c90/experiments/plans/reference/报告核对.md)与原实验解释，不自动移植到图像或新接点。

## 1. 任务、身份与来源

- 问题、输入／输出、质量、模型／processor、dtype、解析、NULL／错误／取消及结果关联是否明确？
- 固定实际源码、版本、运行标识和配置；分清原生系统、项目内部对照、软件 fixture、冷算子和数据库完整查询。
- 谁拥有语义、批次、执行图、调度和模型服务？原生臂保留合理调优机会，不注入 SemLoom 策略或私造持久池。
- 按实际 schema 核对 [provenance.py](../../../code/src/baselines/common/provenance.py) 的角色和字段；组件角色不能替代系统角色，API／UDF 语法本身不能决定是否原生。
- 实测来源和当前文档／Git来源分开，合并或复用声明不增加实库、模型、GPU或性能证据。

## 2. 完整任务与生命周期

- 单查询／一批数据以提交至全部必要结果的时间和有效结果吞吐为主；请求、批次、Job、完整查询各自标明起止。
- 常驻 worker 与已有索引的完整查询，另报启动、首次建库和退出；逐查询原生重建／加载仍留在查询内。
- 设施就绪、SQL就绪、完整应用和冷算子分别命名，不能通过移动计时起点扣掉一条路径独有成本。
- 原生每RM图和workflow持久池如实报告；源码能力、实际创建／加载／销毁次数分列，未采集写 unavailable。
- 查询终点、整批可见返回、模型实际构造位置、清理／持久化／退出及样本单位按[字段口径](对照规范.md#measurement-field-scopes)核对；不由字段名推定包含全部关闭或排除全部加载。
- 部分失败、慢样本、中止、重试及未完成槽位保留身份，不用成功子集代替完整运行。

## 3. 指标与观测缺项

- 有效吞吐写清任务分子、质量要求与共同墙钟分母，原始吞吐并列；GPU利用率及服务指标只作适用解释。
- 文本服务 token 吞吐使用可核验的 prompt＋generation 增量除以同一服务窗口；不求和不同窗口的分片速率，不把输入估算或 `total_tokens/max_jct` 当同口径服务吞吐。
- 累计CPU／actor service、重叠区间和墙钟不能直接相加或相减构造加速；HTTP往返不是纯kernel。
- decode／transport／H2D／kernel／D2H未完整拆分则保留未知；详细计时关闭的0、空finish_reason及缺服务计数不表示零成本或已审计。
- 同时核对 requested 与实际batch形态、工作量及资源；逻辑额度不是实际模型活动或硬显存上限。

## 4. 归因、统计与结论强度

- 源码、原始结果、论文／官方资料、CPU／模拟、推断和候选分开；工程接线不等于研究贡献。
- 保留全部重复及运行顺序，按适用方法报告效应与波动；单次观察只支持该配置的信号。
- 查询内请求不充作独立查询重复；小样本P99／P99.99不能解释成可靠总体尾分位。
- 样本标准差使用n−1；统计方法与实际问题匹配。等价检验和优越性检验分别定义，未检出差异不表示等价。
- cache、生命周期、CPU/GPU与观测开销不匹配时说明差异，不把相关性或源码声明写成根因。
- PNG共享适配、原生batch／流水和池复用不作独有创新；零命中、变慢与质量不足照实保留。

## 5. 可核验交付

- 报告引用实际配置、全部重复／失败、必要原始观测与复算入口；私有原件注明运行标识、校验值及获取方式。
- 派生指标给出公式、单位、分母及计算来源；无法采集的项注明原因，不生成无依据的可排名数字。
- 历史报告保留原数值与来源；更正进入同题报告，现行入口引用权威正文，避免复制摘要继续分叉。
- 按实际影响同步状态、台账与导航；检查本地链接、`git diff --check`及提交前隐私扫描。
