采样／校准／阈值、联合提示、缓存政策和结果解释一致，并核对实际工作与质量。

首版实现单模型文本Map、完整响应适配，以及一条两Map串行链的外部输入验证。
不全面重写已有算子优化，不先建设任意查询图、全表校准、跨行Join或并行阶段展开。
级联和多个真实模型角色等到具体消费者需要时增加；不把单模型连通解释为这些能力已经支持。
PG继续拥有SQL、普通子计划、快照、权限及查询生命周期；外部执行接口不接收原始SQL重新取数。

### 职责与两个接点

```mermaid
flowchart LR
    A[PG合法输入／外部输入] --> B[增量算子适配：原有方法]
    B --> C[完整且已就绪的任务]
    C --> D[原生执行器／SemLoom执行器]
    D --> E[同配置模型服务]
    E --> F[完整响应与完成反馈]
    F --> B
    B --> G[行结果／后继算子]
```

| 拥有者 | 决定与保存的内容 |
|---|---|
| 数据库或原系统 | 合法输入、算子配置、原始行与输出归属、查询取消和错误政策 |
| 算子方法与薄适配 | 提示与解析、方法选择、模型角色、算法必需的等待、当前阶段是否具备执行资格 |
| SemLoom核心 | 已就绪任务的组织、接纳、提交、服务选择、共享容量及结果留存与归还 |
| Daft／Ray后端 | 有限数据块的物理准备、传输和任务执行；池前接入路径不复用原模型请求池，Sema上游原池仍保留 |
| 模型服务 | 实际推理与服务内部批处理；服务配置与资源在成对实验中一致 |

方法接点承接有限输入与继续执行；目标任务接点位于原生请求池、限流、排队及物理批次提交之前。
当前LOTUS与DuckDB AI具有上述池前接点；Sema只在原生HTTP抵达后创建任务，不适用这一执行器替换设计。
全表校准等算法必需的等待继续保留；仅因原实现采用整表物化或逐批返回造成的等待可以替换。
接点之前已被原生执行器限制的供给，不能通过后置HTTP接入自动恢复。
单算子任务接通不等于跨算子流水；后者还要求输出可以及时交给同一方法的后继。

### 公共信息与实现复用

复用[SessionEngine](../../code/src/scheduling/core/session.py)、
[任务与完成接口](../../code/src/scheduling/core/session_contract.py)、
[方法继续执行](../../code/src/semantic_methods/README.md)及现有Daft／Ray传输。
新增适配处理真实供应商差异，不建立第二套调度、排队、容量管理或方法决策核心。
具体类型和跨语言协议由公共入口任务依据LOTUS、DuckDB两个消费者确定，总设计不预定另一套通用接口。

| 信息 | 首版需要保留的含义 |
|---|---|
| 查询、算子、行、阶段和请求身份 | 同一行可有多个阶段；响应乱序不改变归属；物理分组不重写逻辑身份 |
| 完整调用说明 | 原系统已选消息、模型与生成参数；供应商SDK的参数转换需与原生请求核对 |
| 工作量与局部性 | 显式描述来源、单位和校准身份；获取信息与估算的成本计入耗时 |
| 就绪与继续执行 | 只交出合法就绪任务；结果触发下一阶段；输入结束不等于不再有后继任务 |
| 完整响应 | 原始响应体、HTTP状态及必要响应元数据；保留用量、置信信息与错误，原系统解释结果 |
| 所有权与退出 | 接纳前后谁保存输入、谁留存结果；取消、错误、未知远端结果及清理都有明确处理 |

原系统的一次完整模型调用为任务单位。首版Map每行一次；原方法以后生成的多行联合提示保持整体，
不能借数据组织拆分或合并提示。阶段标识本身不能代替真实的数据依赖和执行资格。
成功响应已有原始字节通路；PG文本完成结果会提取字段，固定模型传输会归并错误类别，
因此跨系统结果适配需另行保留完整响应，旧PG默认接口和错误行为继续接受回归检查。
当前方法驱动支持按行串行继续执行，QueryRegistry只登记流数量；不据此声称已接收完整查询依赖图。

<a id="sema-native-executors"></a>
### Sema后置原生执行接入（2026-10-12）

用户已要求并行实现Daft Native、Ray Data及IMLane。复用现有Sema请求服务与公共完整调用表示，
不复制LOTUS／DuckDB接点、不建设另一套调度器。三条路径仍在原请求池之后，保留作者SQL、
提示、联合提示、模型参数、解析和原生供给；不能解释为Sema数据库执行器替换。

| 实施部分 | 复用与新增职责 | 完成要求 |
|---|---|---|
| Sema HTTP接收与回送 | 继承现有`SemaRequestService`；将当前已抵达的有限请求快照交给公共`NativeCallExecutor` | 不等待整查询请求到齐；同一原始正文只发送一次；相同正文的不同请求分别关联 |
| Daft Native | 复用Daft0.7.21原生异步函数图；公共执行器来自`25935d02` | 核对实际库、完整响应、错误、取消、已接纳输入和未写出结果的容量 |
| Ray Data | 复用Ray2.56.1 HTTP Processor；独立调用方拥有Ray会话 | 不套用SemLoom Core；检查实际图执行、无自动重试、乱序结果和退出清理 |
| IMLane | 复用另一个实施会话的作者DBEnd构建和完整HTTP调用入口 | 只增加Sema调用侧适配；没有实际可用构建时明确写pending，不用模拟执行器冒充 |
| 共同入口与记录 | 父任务整合Sema路径选择、资源参数和阶段记录 | 旧原生、薄转发及SemLoom入口保持；不改原系统算子设置 |

公共调用采用`NativeCall`和`NativeCallOutcome`，保存完整正文、必要HTTP头、请求出现身份、
期限及响应容量；状态码、重复响应头、原始正文和传输错误交回现有服务处理。
`row_id`在这条路径中仅承载HTTP请求序号，不能标为Sema源行身份。
执行函数采用`iter_batch(calls, cancelled=..., timeout_s=...)`；IMLane适配遵循相同调用形式。
只有输入快照与完成回送由Sema适配处理，原生图或IMLane拥有批内任务执行与并发。

接纳后保留请求或响应名额直到HTTP写出或异常退出，最多128项；每个快照最多128项、32MiB，
单请求及响应最多8MiB、期限120秒。原查询请求总数和SQL期限沿现有显式配置。
一次只有一个原生快照执行，后续已抵达请求留在有限队列；不引入等待填满、长度排序、
自动并发调参或跨查询调度。该源适配可能影响供给，因此快照大小与数目必须报告，
性能比较保留原生直达、薄转发和同核心静态SemLoom，并逐项核对真实调用内容与数量。

阶段记录分别说明：服务/库初始化，HTTP抵达至读完正文，等待取得输入名额，快照形成，
原生图开始至结果被调用侧收到，完整响应收到至HTTP写出，以及SELECT提交至SQL结果消费结束。
图开始不是实际模型POST起点，图返回不是GPU纯计算；模型HTTP起止只采用实际网关或执行kernel观测。
不同进程时钟不直接相减；缺少原池前就绪、源行关联或模型内部时间时写unavailable及原因。
请求P99使用服务抵达至写出或实际模型HTTP两种明确口径，整查询P99另计，均附样本数及最大值。

先以本地确定性服务验证：顺序到达不等整查询、等值请求、乱序完成、原始正文/完整响应、
非成功HTTP、传输错误、超时、取消与慢写出。再用实际Daft/Ray及作者IMLane执行无模型往返，
保留失败与实际清理报告；子任务不占GPU、不重启共享Ray、不修改共享模型服务。
父任务共同验证通过后再准备短真实模型试跑，另记实际源码、环境和运行计划，
不将本地替身检查写成真实模型性能证据。

实际库之后，父任务另做作者SQL正确性试跑：Daft与Ray Data各8行一次，原作者二进制摘要必须匹配，
模型响应由本地确定性HTTP服务提供，合计最多16次fixture POST、真实模型0。
每次使用8CPU、零GPU，Ray按现有查询入口使用256MiB对象存储，独立短目录和动态localhost端口，
总期限5分钟、单查询120秒；首次错误停止这项试跑并保留，修订后使用新的运行标识。
检查实际SELECT结果、原生输入/请求/消费计数、名额归还、正常图清理及阶段样本；
这些耗时只用于工程诊断，不能作为模型性能或饱和证据。IMLane先通过真实DBEnd往返，再按同样方式追加作者SQL。

### 成对比较与观测

先保留未修改的原生系统，再按实际可实现的共同入口增加适配后原生执行、SemLoom固定执行和待测物理方法。
共同入口若改变原生执行流程，适配后原生路径单独命名；新增适配与序列化成本通过原生路径核对。
同一适配后的短算子链可比较分阶段等待与逐行继续执行；不借此声称已经替换原数据库完整执行器。
原生系统各自保留合理配置，在同资源上限下比较；线程数、批大小和HTTP实际在途数分别记录。

| 指标 | 起止与解释 |
|---|---|
| 完整应用耗时 | 查询准备入口至统一消费端读完结果，保留各系统准备工作明细 |
| 就绪查询耗时 | 数据、连接和组件就绪后，实际提交SQL／原生接口至结果全部读完；不从完整耗时减去准备时间估算 |
| 请求端到端延迟 | 完整任务已就绪、尚未本次执行器准备与排队，至原调用者取得完整响应；供给受限路径缺起点时写不可观测 |
| 数据执行阶段 | 输入供给、方法准备、组织、表示／传输、接纳等待、模型、返回／消费和中间结果留存分别记录 |
| 质量与工作量 | 行／任务关联、输出质量、实际调用与各角色token、失败／重试及资源峰值；客户端尝试不冒充服务端执行证明 |

请求与整查询分别保留全部样本、P99与P99.99。统计单位为模型调用或完整查询，不将一次联合提示的多行当独立请求。
样本不足时报告有限样本分位值与最大值，不宣称已测准总体极端尾部。
按执行时延自适应选择方法的系统，先固定方法选择；实际任务集合或质量不同的运行另报差异。
请求服务补充观察保留原生直达、透明转发和SemLoom服务三条路径，记录上游供给与后置等待。
每次模型POST只累计记一次；旧透明观察代理不因记录事件而变成新的执行器。

### 任务完成时间与工作量的解释

后续比较关注保持语义、质量与资源约束时的到达至结果可用时间、共享服务质量及有效吞吐。
下列口径用于解释本方案的测量；已有结果按原记录保留，未采集字段写明缺项与原因，不用估计值补齐。

完整任务时间为`T_job = t_result_available - t_arrival`，其中`t_arrival`指预定的任务到达／释放时刻；
就绪后的时间为
`T_ready = t_result_available - t_ready`，其中就绪点及其满足的条件在配置中预先声明。
两者采用同一结果终点，后者是前者的嵌套区间。预热且可复用的执行设施可作为实验前提，
其建立成本与复用历史另列；任务特有的读取、准备、估计、组织和准入等待仍在`T_job`内。
多查询从各自预定到达／释放时刻计时，终点包含任务要求的业务解析、交付或写回；
离线gold评价另计。结果在内存可用与持久写回属于不同任务终点，比较时保持一致。

历史原Movie的ready query固定为原SQL／API提交至统一消费EOF，完整query另含本次查询准备，
冷启动与清理在slot中保存，官方评价在EOF后单列；该边界及原值继续有效，
不追认成外部到达计时，也不把旧`release`字段名称当作外部到达证据。
[已有阶段分析](../results/diagnostics/native_sembench_model_dual_supplement_20261012/README.md#retained-stage-analysis)
给出实际字段、区间并集与缺项，不代表已实现所有业务终点。

准备、传输、等待、模型及消费跨度可能并发或嵌套，不能直接相加为完整任务时间。
阶段解释采用可比较的时钟、明确的事件记录者与结果归属；跨进程跨度有同钟或校准依据才相减，
无依据时保留各自时长。互斥区间分解与关键路径另行说明，累计资源工作不等同墙钟。

逻辑请求数、物理批次数与资源工作量分别报告，token、帧、字节及驻留等工作量写明单位与来源。
多个独立请求装入同一物理批次时保留完整消息、生成参数、输出关联及错误规则；
拼接提示或改变语义属于另一任务配置。固定工作量`W`在同一完成窗口的有效吞吐`W/T`与完成时间
互为换算，不能记为两项独立收益；稳态或开放到达吞吐另按实际窗口及完成工作解释。

长短查询各自报告完成时间与推进，独占参照使用相同资源与任务条件。
可接受的后台损失来自明确的应用／服务假设及实际对照，不新增统一百分比门槛。
查询P99使用查询完成样本；[匹配Q2](../results/diagnostics/native_sembench_model_dual_supplement_20261012/README.md#matched-budget-repair)
的每路径每拓扑四次测量与480个请求分别计数，两个服务历史亦分开，不能用请求数放大查询样本量。
全部重复值、失败、超时与未完成状态保留；未完成任务不当作已知完成时长或从记录中消失。

执行设施缓存、结果缓存、模型前缀缓存、输入准备表示缓存与文件／系统页缓存各自记录设置及复用历史，
不能从其中一种复用推定另一种收益。实际观察与记账开销保持在所属测量中，不估算后扣除。
GPU利用率、队列与请求延迟用于解释供给和瓶颈，任务级收益由相同语义、质量及资源下的任务结果支持。
