## M1：供给不足，停止条件阶段

各点统一：候选L128，Core输入/结果各128MiB，PG留存256MiB/暂存4MiB；
[可达性预检](raw/m1-preflight.json)通过，每个点确实达到配置的 HTTP 峰值。
各128行、1次预热＋3次交错测量，筛查3,072次POST；之前PG/direct各8行正确性，共16次。
完整 JCT 从调用准备开始到最终 EOF，包括查询内记录开销，常驻 gateway/model 启动另记。
有效吞吐＝128/JCT；完整配置、原始重复、逐行等待和资源计数见[筛查记录](raw/m1-comparison.json)。

不把PG/4命名为调优最优点，不把direct/64当服务上限。**W调参、独立评价、full/compact观测对照均未执行**，
不转用其剩余额度，不增样本或改阈值。

合法但分类错误的14行没有从分母剔除；该结果不是 SemFilter 质量资格。

**观察与解释分开：**PG/4第一次测量 JCT22.328秒，对应gateway采样CPU22.21秒；PG/16为24.297/24.48秒，
PG/64为24.625/24.92秒。逐行平均“提交到终态”分别0.692/3.001/11.961秒；
“算子交付到客户端”分别6.268/3.915/0.245秒，后者包含普通客户端结果缓冲。
完整请求链与CPU行为值得排查，但这不是纯PG开销的测量，尚不能确定观测、事件循环或传输各占多少。
full/compact未运行，因此尤其不能把日志影响排除，也不能将CPU相关性写成已证根因。

## F：真实 CLIP 数值与指定错误/取消通过

CLIP ViT-B/32与processor均为revision `3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268`，
float32、224输入、投影512维、L2归一化、TF32关闭。12张COCO图像加2次重复、1个NULL；
3张候选因既有256KiB编码上限排除，未重编码。模型/图像SHA及排除记录见资产文件。
三条路径均先2次预热，再测3轮14次非NULL前向；同步参考与分阶段路径保持同一解码、归一化和模型。
独立reference是独立调用，仍复用同一CLIP组件；它检查路径一致性，不能排除三条路径共有的模型/处理器实现错误。
