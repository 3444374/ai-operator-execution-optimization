# Palimpzest fixed-version adapters

PZ owns semantic operators, optimization and legal DAG dependencies. This module
provides controlled private seams for PZ `0.8.2.sem_agg`, commit
`6efc19841c49d727ce42f5c2dd55e7433601d2d9`; it is parallel to LOTUS.
The [comparison contract](../../../../experiments/plans/reference/对照规范.md#execution-comparison-levels)
separates complete-system quality/cost/time from execution of one selected plan.

Deployment declares CPU/GPU, memory and model-service budgets, and chooses a fixed
configuration or a verified native automatic mode. PZ determines semantic readiness;
the selected backend owns dispatch, workers and backpressure. The thin adapter adds
no common concurrency controller. Its finite prepared-request/stack and snapshot
limits bound retained memory, rather than claiming to tune backend concurrency.
System comparisons freeze configuration rules and permit reasonable backend-specific
concurrency; capacity-matched mechanism experiments state the common work unit separately.
HTTP request budgets and vLLM sequence/token budgets remain distinct. Native Ray pool
autoscaling does not prove HTTP/GPU-window tuning; IMLane's declared `n` and SemLoom's
declared cap remain explicit. Dispatch within a cap is not verified online cap tuning.
Existing fixed-configuration evidence retains its original identity; these rules do
not require historical reruns or a new tuning matrix.

`completion_bridge(completion=..., observer=...)` keeps the original Generator's
prompt factory, parser, statistics and exception defaults. It substitutes the
module-local LiteLLM reference and guards source hashes. A configuration or
observer error fails the adapter; a genuine model or parser error retains the
upstream False/None default and is independently recorded as an invalid prediction.
The bridge rejects overlap and retains its patch while any started Generator is
still active. Its return does not independently prove that remote work stopped.

`freeze_best_plan(processor)` selects once with the original optimizer.
`execute_frozen_plan(processor, frozen)` calls the original execution strategy
with that same plan object, rejecting changed operator/generator parameters.
This helper requires no validator; sampled/validated system execution must use
the original processor rather than silently skipping sentinel work.
`plan_id` alone is insufficient: source contents, configuration, dependencies,
request hashes and service/cache state remain separate runner evidence.

The [Movie runner](../../../scripts/experiments/run_sembench_palimpzest.py)
defaults to original native execution and uses unchanged Q3/Q2 method bodies from SemBench
`c814e3807e72d4cf876b852b17e77f3cc94575c2`. It captures their terminal explicit
`Dataset.run(config)` call to avoid the generic runner's Gemini fallback, then
uses PZ's original run with explicit `QueryProcessorConfig` and parallel workers.
Q3 audits complete selected filtering and COUNT; Q2 retains LIMIT5 and records
actual submitted/completed work rather than assuming five requests.

Use the [configuration template](../../../../deploy/autodl/sembench_palimpzest.example.json)
and [separate driver dependencies](../../../requirements/palimpzest.txt).
Runtime paths and `FixedModelConfig` stay outside Git. The old vLLM enum is only
an explicitly recorded transport binding to one exact loopback `/v1/models`
identity. Unknown names never select Gemini or another provider. Upstream model
card costs are not actual service prices; missing usage and monetary cost remain
unavailable. Data preparation, service preparation and query execution are distinct.

The selected plan retains its complete metadata digest and immutable initial anchor.
Repeated metadata GETs compare a versioned stable identity: only model `created`
and permission `id`/`created` values generated by vLLM on each response are normalized.
Field presence, accepted types, array order and every other field remain bound,
including model roots, context limits, permissions and unknown extensions. Each
fixed run records the bounded decoded GET body and its digest separately; partial
or unavailable bodies and metadata failures remain explicit evidence.

```bash
export LITELLM_LOCAL_MODEL_COST_MAP=True HF_HUB_OFFLINE=1
PYTHONPATH=code "$PZ_DRIVER_PYTHON" code/scripts/experiments/run_sembench_palimpzest.py \
  --config deploy/autodl/sembench_palimpzest.example.json --data-preflight
PYTHONPATH=code "$PZ_DRIVER_PYTHON" code/scripts/experiments/run_sembench_palimpzest.py \
  --config deploy/autodl/sembench_palimpzest.example.json --preflight
```

`--execute` acquires the existing host-scope lease with stale recovery disabled,
verifies local model metadata and writes a new private run directory. CPU fixtures,
real-model runs and each of PZ+SemLoom/IMLane/Daft/Ray Data need separate evidence;
the completion seam is not a transfer of the entire query DAG to those backends.

The newer attachment review concerns PZ `807ed301`/1.5.3, not this SemBench tag.
The completion bridge remains a native/diagnostic boundary. The adapted path in
[`query_execution.py`](query_execution.py) privately reuses the original parallel
strategy's function bodies and queues before its per-row pool. Non-model operators
run locally; model operators suspend on the query thread when the original SDK has
prepared a complete request. [`prepared_sdk.py`](prepared_sdk.py) returns the full
HTTP response to the same SDK/Generator stack for parsing, statistics and records.
It uses greenlet 3.5.6 without switching stacks between threads or replacing global
PZ executor state. Terminal futures release introduced request and stack references.

This first controlled profile is `fixed-local-nonredirect.v1`: the query-owned SDK
client disables redirects before request preparation, then preserves that prepared
request's body, headers and timeouts. A 3xx response keeps the original SDK/PZ error
default and separate failure ledger, then stops further adapter dispatch. This does
not qualify the original SDK's default redirect behavior. Zero SDK sends, a second
send, identity changes and unknown remote outcomes fail the adapter; ordinary
provider/parser failures retain the original False/None defaults and invalid ledger.
Unknown work keeps its responsibility and blocks new work. An exhausted finite
batch is not evidence that a query or remote service has ended.

Native-adapted response closing and actual-send observation are attempted independently.
The request or cancellation error keeps priority; later close/observation failures are
notes. A close failure after a complete response still fails the call, and an unknown
transport outcome still prevents reuse. Integration keeps the native capacity contract
and revalidates exact source guards; earlier runtime evidence remains at its frozen source.

[`select_fixed_movie`](../../experiments/palimpzest/fixed.py) selects the original
Movie Q3 plan once. It records source/schema/UDF, prompt/parser, model, dependencies,
disabled client cache and caller-verified service/cache declarations; `fresh(run_id)`
constructs independent operators, sources, Generators and the original strategy.
[`execute_fixed_movie`](../../experiments/palimpzest/fixed_runner.py) never reoptimizes.
It separates original-native execution from native-adapted, Daft, Ray Data, author
IMLane CP/Ray and SemLoom. `BackendRunProfile` currently accepts only explicit fixed
deployment budgets; native automatic tuning remains unsupported. The original
zero-survivor empty relation is preserved and marked compatibility-invalid rather
than silently changed to COUNT=0.

### Public fixed-plan execution and timing

The same script accepts `schema: "semloom.sembench_palimpzest_fixed.v1"` with the
original path/budget fields plus `fixed_execution`. The original
`semloom.sembench_palimpzest.v1` configuration and native Q2/Q3 behavior remain supported.
The fixed scope is Q3 only. Copy the existing configuration, change its schema, and
add the following block with real service/cache/dependency/deployment digests;
`limits.pz_workers` must match `native_options.max_workers` (20 in this example):

```json
{
  "arm": "native-adapted",
  "run_id": "movie-q3-adapted",
  "environment": {
    "service_config_sha256": "<service-config-sha256>",
    "service_cache_sha256": "<service-cache-sha256>",
    "dependency_lock_sha256": "<dependency-lock-sha256>"
  },
  "backend_profile": {
    "deployment_budget_sha256": "<deployment-budget-sha256>",
    "mode": "fixed"
  },
  "limits": {"pz_workers": 20, "max_pending_calls": 32, "max_batch_rows": 16},
  "backend_options": {"max_workers": 4}
}
```

`--data-preflight`, `--preflight` and `--execute` select the same configured arm.
Each native backend retains its existing configuration and concurrency controls:

| `arm` | `backend_options` |
|---|---|
| `original-native` | `{}`; use `limits: null` and original PZ controls |
| `native-adapted` | `{"max_workers": 4}` for its original SDK I/O pool |
| `daft` | `{"graph_options": {}}`; existing `NativeGraphOptions` overrides are allowed |
| `ray-data` | `{"graph_options": {}, "ray_address_env": "PZ_RAY_ADDRESS"}` |
| `imlane-cpython`, `imlane-ray` | `{"graph_options": {}, "call_config_env": "PZ_IMLANE_CALL_CONFIG"}`; existing private call config must match the arm |
| `semloom` | `{"max_active_requests": 8, "physical_config_env": "PZ_PHYSICAL_CONFIG"}` |

Ray addresses name an existing caller-owned cluster; automatic/local cluster creation
is refused. SemLoom uses the existing `RayMapConfig` with
`response_mode="native-call-full"`, `payload_backend="daft"`, no preparation and no
borrowed worker pool. This entry owns its query workers; the local SemLoom diagnostic
remains available through the Python helper. Model services and IMLane Coordinators
remain caller-owned. Preflight checks configuration and PZ/SDK libraries; actual
vendor execution and physical cleanup require their own runtime evidence.

The [runner implementation](../../experiments/palimpzest/runner.py) selects once,
then starts the fixed-query clock before fresh state, event writer, Ray connection,
observation gateway and executor/`SemLoomProgress` construction. Only adapted arms
use the existing HTTP-preserving gateway; it charges the durable budget before
forwarding, without changing backend scheduling. The native arm uses the existing
actual-send SDK observer. Selection/optimization is separately reported and is not
repeated inside this fixed-plan execution interval.

| Evidence field | Boundary |
|---|---|
| `query_seconds`, `total_seconds_with_fresh_state` | Legacy meanings retained, including evaluation; the latter adds only the helper's recorded fresh-state duration |
| `result_ready_seconds` | Helper entry through complete original PZ records/COUNT and SDK parsing; truth/quality audit excluded |
| `full_query_seconds` | Outer fixed-query submission through those complete results, including all per-query objects above |
| `outer_query_preparation_seconds` | Outer submission through helper entry, already included in `full_query_seconds` |
| `quality_evaluation_seconds` | Relation/truth/quality audit, also retained if evaluation fails |
| `service_startup_seconds` | `null`: external service startup is not measured by this runner and needs separate evidence |

Direct helper calls without `query_started_ns` report `full_query_seconds: null`
with an explicit scope reason. These new fields do not relabel historical timings
or grant performance qualification.

Strategy close independently attempts finish, safe continuation cleanup, SDK close
and its final report, preserving the first error. A stopped finite reader does not
prove that a native SDK sender future ended: `sdk_in_use` retains that responsibility
until it completes. An active reader/sender keeps the SDK open. The outer runner
also respects existing IMLane external-cleanup markers and failed resource closes.
Unsettled work retains its executor/gateway/SDK dependencies and host lease, records
`owner_cleanup_pending`, and exposes the live owner as `error.pz_execution_owner`
for explicit caller cleanup. It does not recover stale leases or replace an unknown
runtime automatically. Normal cleanup closes query-owned resources and releases
the lease; caller-owned Ray connections and Coordinators are preserved.

The [CPU regression record](../../../../experiments/results/diagnostics/palimpzest_movie_20261015/README.md#query-timing-owner-regression)
separates deterministic control-flow fixtures and localhost original-SDK execution
from unchanged historical model/backend evidence.

Finite Daft/Ray Data/IMLane paths reuse the existing complete-call native API graphs.
[`SemLoomProgress`](semloom.py) instead keeps one query Job and open operator flows,
releasing results before resuming the original continuation and sealing only when
the method ends. Explicit `RayMapConfig(response_mode='native-call-full',
payload_backend='daft', ...)` uses the existing Daft materializer, Ray objects and
HTTP actors with verified source/model identity on the driver's single live node.
The shared transport reuses the existing NativeCall HTTP kernel. `physical=None`
is a local diagnostic. Work=1 denotes request count, not calibrated GPU work.

The adapted slice accepts single-model LLMFilter, single-field ONE_TO_ONE bonded
conversion, ordinary scans/predicates/projection and structural COUNT. It rejects
LIMIT/join/distinct/semantic aggregate, multi-field follow-ups and unverified shapes.
The [qualification record](../../../../experiments/results/diagnostics/palimpzest_movie_20261015/README.md)
separates source checks, synthetic HTTP backend runs and real model evidence; the
implemented interfaces do not by themselves establish model parity across backends.
