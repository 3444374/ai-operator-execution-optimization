# learning/AGENTS.md

继承根规则。学习路径见 [README.md](README.md)。

- 按用户当前疑问解释，允许使用教程、问答或时间线；局部问题不展开整套实验。原始结果和论文正文留在各自目录。
- 术语放回具体场景：数据来源、所在进程/内存、经过的 API、执行者和去向。用户询问实现位置时，
  映射到当前源码中的脚本、函数与调用阶段，避免沿用过时符号。
- 讲 Ray 时分清提交得到 `ObjectRef`、worker 执行、`ray.get` 取回和数据库 writeback；另区分
  Ray 的任务执行角色与 actor 异构化、去中心化协调等架构选择。
- 讲 embedding 时说明实际计算位置；项目的外部 Python/Ray worker 与明确讨论的库内模型/UDF 分开。
- 讲 GPU 时说明它是外部模型服务的计算端点；GPU kernel 或库内 GPU 算子优化不是本课题主线。
  主动机与归因优先来自同一 GPU-backed E2E 的画像和消融，CPU/fake 历史结果仅用于预研和解释工具。
- 复杂数据流需要时配最小链路；数值图来自原始 CSV/报告，正式图按 `figures/AGENTS.md` 制作。
  已有图或短文足以解释时复用，库 API 按需查源码或官方文档。
- 比喻最终回到实际系统与证据；按根 §4 区分事实、模拟、推断和待验证，不为教学简化改变事实。
- 比较业界实践或新增文献依据时，读 `research/AGENTS.md` 与相关一手材料，分清本地实现、外部
  worker/vectorizer、数据库内扩展和应用层 ETL/服务的实际角色。
- 新事实影响既有讲解时才同步；研究问题和核心判断由用户决定，已有决定继续执行，新增或改变决定时再确认。
