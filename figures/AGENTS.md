# figures/AGENTS.md

本文件继承根 `AGENTS.md`，只增加图资产的生成、证据和视觉验证规则。资产入口与当前图清单见
`README.md`；具体图的历史决策见 `audit/`，不在规则文件中复制。

## 1. 资产与复用

正式材料引用本目录的单一资产；具体存放位置查 README，不在开题、学习或实验结果目录维护副本。

## 2. 图的任务

新增图或改变论证时，在目标 audit 说明类型、结论、来源、使用位置和不能推出的结论；仅调整排版
或导出时复用已有说明并记录检查结果。已有图能回答同一问题时修改其可编辑源；证据不稳、数据过少
或表格更清楚时使用文字或表格。

## 3. 数据图

- 从项目内 CSV/JSON/manifest 或明确可复算表生成，不手填或凭报告文字重造数字。
- 使用可复现脚本统一计算、配色、字体、轴和导出；需要专门的数据剖析或统计图方法时，按需参考
  `scipilot-figure-skill` 或 `nature-figure` 的对应部分，沿用已有绘图链和已确定的用户选择。
- 主图标注 workload、系统臂、单位、重复/聚合方式、warm-up 处理和证据层级；caption 给出数据路径、
  主要观察与限制。
- 轴范围必须诚实；截断轴需要显式说明。误差棒、显著性和归一化必须给公式/统计方法。
- fake/CPU/smoke/单次 rehearsal 不使用会让读者误判为正式 GPU database-E2E 的标题或配色层级。

## 4. 概念图与方法图

- 使用可编辑源生成 SVG/PNG，不把截图当源图；设计核心论文图时结合当前 audit 已确认的布局，
  需要专门的论证结构建议时再参考 `figure-designer`。
- 一个图只承担一个上位问题。组件按真实所有者和数据流排列，区分数据库、外部执行、模型服务、
  观测/控制与结果写回。
- 项目颜色语义保持稳定：蓝色=研究内容一，橙色=研究内容二，紫色=共同组件/模型执行，
  绿色=结果/评价/写回，灰色=观测、注释或外部组件。颜色之外再用文字/形状编码。
- 标题、卡片、边距、字体和箭头风格一致；布局以可读性和真实关系为准。
- 连线只表达必要关系。箭头从明确的源组件轮廓到目标组件轮廓，不穿过无关框、文字或画布；空间不足时
  调整布局，不用漂浮箭头头部补救。
- 图中只放短语和关键量，完整解释进入 caption/正文。内部结构名首次出现时写明中文作用。

## 5. 对外语言与图文一致性

- 图题写清对象、比较条件和可读出的现象。
- 图中全部文字遵守根 `AGENTS.md` §6 的禁词要求。
- 报告、PPT、图例、坐标轴、caption 和讲稿使用同一术语、数值和证据适用条件。
- 内部结构与指标在图内或相邻 caption 解释作用。

## 6. 导出与验证

正式图进入 `report_main/` 前必须：

- 能从源数据/脚本或可编辑设计稿重生成；
- 按用途导出 SVG 以及高分辨率 PNG；单格式例外写入 audit；
- 程序检查画布尺寸、元素越界或重叠、残留内部词、缺失颜色/字体和引用路径；
- 以最终导出尺寸实际打开 PNG/SVG，检查文字裁切、卡片边框、箭头起止、图例、对比度和缩放可读性；
- 在 `audit/` 记录来源、生成命令、目视结果、已知限制和替代关系。

尺寸与导出要求查目标图 audit；调整策略图细节时参考 `audit/strategy_figure_micro_design_points.md`，
调整系统架构图时参考 `audit/system_architecture_ai_data_execution_audit.md`。

## 7. 更新与清理

- 图的路径、用途、数字或主结论变化时，同步 `figures/README.md`、对应 audit、生成脚本和所有实际
  引用它的报告/PPT/学习材料；只改导出元数据时不机械改写正文。
- 删除或替换图前用 `rg` 检查全仓引用，并确认旧文件不含唯一源、人工编辑或审计价值。
- 本次任务生成、可重生成且无引用的临时导出可随任务清理；已作为审计证据的图、正式图、源脚本、
  audit 和人工编辑长期保留。既有素材先核对来源、引用与恢复路径，删除仍需用户确认。
