## 1. 修改目标

本轮只修正会造成研究对象或实验结论误解的图中文字和关系，不统一重做版式。修改后应满足以下要求：

1. 工作描述、代价估计和运行状态是三类不同信息。
2. 研究方案图中的候选模块不会被读成已经完成并取得收益的系统。
3. 代价估计的主要信息去向是数据库优化器和多 SQL 工作负载调度模块。
4. 实验图使用正式、具体的分组名称，并保持现有数据、坐标、误差和统计口径不变。

## 2. 保持不变的内容

- 图 1、图 4、图 7 至图 11 不修改图片。
- 四张待修改图片的画布尺寸、四色体系、主卡片位置和总体阅读方向不变。
- 图 6 的原始数据、柱长、数值标签、横轴范围、均值和标准差不变。
- 不修改桌面 `0819.pptx`，也不生成 Word 文档。

## 3. 图 2：数据库与模型服务之间的 AI 数据执行层

类型：研究问题与系统层次关系图。

当前主要问题是底部把“代价估计 + 状态观测”写成一个共同组件，容易使读者认为两者来源和用途相同。

最小修改如下：

- 保留数据库侧、AI 数据执行层和模型服务侧三栏结构。
- 中间上方仍保留两项研究内容。
- 将底部区域改成两个并列信息块：
  - `AI 算子代价信息`：输入规模与历史测量产生预计时间和资源需求，箭头返回数据库优化器与多 SQL 调度。
  - `运行状态观测`：记录排队、缓存、完成速度和作业进度，箭头返回上游提交与路由。
- 删除“共同使能：代价估计 + 状态观测”的合并标题。
- 将 `research gap`、`shared credit`、`idle borrowing` 等图内表达换成报告已经采用的中文解释；方法名称只作为候选思路出现。

## 4. 图 3：分阶段工作量描述与数据组织

类型：研究内容一的方法概览图。

当前主要问题是 `confidence / uncertainty / calibration` 位于 WorkDescriptor 内部，容易把代价估计输出理解为工作描述的必备字段。

最小修改如下：

- 保留 Source/Input、Prepare、Model/Result、候选组批和 BatchRequest 的现有位置。
- WorkDescriptor 只保留四类运行前已知信息：记录与作业身份、阶段工作特征、数据局部性、服务目标或优先级。
- 在 WorkDescriptor 旁增加一个尺寸较小的 `可选代价估计结果` 标签，内容为预计时间、误差范围和校准状态。该标签不嵌入 WorkDescriptor 卡片。
- 把 `Work Estimation` 改为 `分阶段工作描述`，避免把所有工作特征都写成预测值。
- 保留四种候选组织思路，不增加新算法，也不改变现有箭头方向。

## 5. 图 5：数据库记录经过组织、调度和模型执行得到结果

类型：系统总体关系图。

当前主要问题是代价估计与 WorkDescriptor 合并，图中又使用了 `contract`、`frozen-static` 和抽象的“闭环”表述。

最小修改如下：

- 主执行路径仍为 PostgreSQL 与 Daft、WorkDescriptor、Work Organizer、提交与多作业调度、文本或图像模型后端、结果收集。
- 将 `WorkDescriptor + 代价估计` 改为 `WorkDescriptor`，其中只列工作特征和作业信息。
- 在主路径上方增加独立的 `AI 算子代价估计` 小模块。输入来自 WorkDescriptor 和历史测量，输出指向 `数据库优化器 / 多 SQL 调度`，不把该输出无条件连到全部运行时模块。
- `source contract`、`公共状态 contract`、`结果 contract` 分别改为 `统一输入字段`、`统一状态记录`、`结果完整性检查`。
- `safe capacity` 改为 `运行前测得的请求数和工作量上限`。
- `frozen-static` 改为 `参数在运行期间保持不变的参照方法`。
- 标题改为具体描述数据库记录、请求组织、提交、模型执行和结果返回，不再使用没有展开动作的“闭环”作为标题关键词。
- 保留实线数据流和虚线状态返回，但每条虚线只连接实际采集状态与使用该状态的模块。
